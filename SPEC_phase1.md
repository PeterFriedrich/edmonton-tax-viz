# Phase 1 Spec: Edmonton Revenue Per Acre — Static Choropleth

## Goal

Produce a static choropleth map showing assessed value per acre by neighbourhood across Edmonton, generated by a reproducible Python script using only free, publicly available data.

---

## Deliverable

A saved image file (`output/edmonton_value_per_acre.png`) showing Edmonton neighbourhoods coloured by assessed value per acre, from a single entrypoint script.

---

## Inputs

| File | Source | Format |
|------|--------|--------|
| Property assessment data | [Edmonton Open Data](https://data.edmonton.ca/City-Administration/Property-Assessment-Data-Current-Calendar-Year-/q7d6-ambg) | CSV (~448k rows) |
| Neighbourhood boundaries | [Edmonton ArcGIS](https://www.arcgis.com/home/item.html?id=558aec1b4d504f809cbbfa774c611230) | GeoJSON or Shapefile |

---

## Processing Steps (kept separate and testable)

Each step should be its own function or module — not one big script.

1. **`load_assessment.py`** — Load and validate the assessment CSV. Output: cleaned DataFrame with columns `neighbourhood_name`, `assessed_value`.
2. **`aggregate_by_neighbourhood.py`** — Group by neighbourhood, sum assessed values. Output: DataFrame with `neighbourhood_name`, `total_assessed_value`.
3. **`load_boundaries.py`** — Load neighbourhood boundary GeoJSON. Output: GeoDataFrame with `neighbourhood_name`, `geometry`, `area_acres`.
4. **`join_and_calculate.py`** — Join assessment totals to boundaries on neighbourhood name. Calculate `value_per_acre = total_assessed_value / area_acres`. Output: GeoDataFrame ready for mapping.
5. **`plot_choropleth.py`** — Render choropleth map and save to `output/`. No analysis logic here.

---

## Stack

| Tool | Purpose |
|------|---------|
| `pandas` | Data loading and aggregation |
| `geopandas` | Spatial joins and area calculation |
| `matplotlib` | Rendering and saving the map |
| `pyproj` / `shapely` | CRS handling (area calc needs projected CRS, not lat/lon) |

No database, no web framework, no GIS software required.

---

## Out of Scope (Phase 1)

- Cost side (no service cost allocation yet — revenue only)
- Interactive or 3D visualization
- Parcel-level granularity (neighbourhood aggregation only)
- Hex bin grid
- Per-ward or per-councillor breakdowns
- Any web output

---

## Acceptance Criteria

- [ ] Script runs from a clean environment with `pip install -r requirements.txt`
- [ ] Each processing step can be run and inspected independently
- [ ] Output map clearly distinguishes high vs. low value-per-acre neighbourhoods
- [ ] Neighbourhoods with missing or unmatched data are flagged (not silently dropped)
- [ ] CRS is explicitly set and projected before area calculation (not assumed)
- [ ] No hardcoded file paths — inputs and output dir configurable via constants at top of entrypoint

## Notes

- Neighbourhood name matching between the assessment CSV and boundary file will likely need fuzzy matching or a lookup table — treat this as a known rough edge
- Assessment data includes tax-exempt properties (government, nonprofits) — flag these rather than silently including or excluding
- Condos: multiple units share one land record; this inflates value-per-acre for high-rise parcels, which is actually correct behaviour for this analysis
