## 3. Technical Learnings

- ⚠️ **A doc that pins a count becomes a trap when the count moves.** The
  excluded-file note was *correct when written* and actively misleading 24 hours
  later, because it hardcoded 25 next to a rule whose output grows with every
  notebook export. The durable form states the rule and says re-run it. This is
  the same failure family as a stale blocker in `TODO.md`
  (`todo-can-lag-executed-work`) — the doc is right about the mechanism and
  wrong about the world.
- ⚠️ **Sizes in `VIZ_STACK.md` are KiB/MiB written with decimal symbols.**
  Confirmed by conversion on five independent files (8.00e6 B = 7.63 "MB",
  2.97e6 = 2.83, 1.09e6 = 1.04, 463735 = 453 "KB", 1245838 = 1.19 "MB"). Before
  concluding a file changed size, check which unit the old number was in.
- **Green CI is not evidence a fails-open test ran.** `fetch-depth: 0` was added
  *and then* the run log was grepped for the actual `git fetch` command line to
  confirm no `--depth`. A test that returns early on a shallow checkout reports
  the same "passed" as one that checked.
- **A scratch clone taken before you commit measures the OLD file.** The first
  falsification run showed 3 tests where the edited file has 4 — the clone
  predated the commit. Caught, committed, re-ran, got the real result
  (`commit-before-falsifying`, live instance).
- **`git clone /path` of a repo with uncommitted work silently gives you HEAD.**
  Same root cause as above, worth stating separately.
- **Longest-key-first matching matters in a path rewrite**: a naive alternation
  rewrites `/home/opc/research/foo.md` by matching the bare `foo.md` key and
  produces `/home/opc/research/research/...`. Sort keys by length descending.
- **Full repo history is 20.7 MiB packed across 1,461 commits** — `fetch-depth: 0`
  is cheap here. Measure before assuming it isn't.
- **`gh repo`-adjacent gotcha unchanged from S173**: nothing new hit this
  session, but all three PRs were created with `gh pr create --base master`
  explicitly.
