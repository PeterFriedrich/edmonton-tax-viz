## 4. Technical Learnings

**Methodology discovery (IMPORTANT — Peter is acting on this):**
- The project is titled "Revenue Per Acre" but the code computes `value_per_acre = total_assessed_value / area_acres` (`join_and_calculate.py:50`) — **assessed value, NOT revenue**. No mill rate is applied anywhere in `src/`.
- Code + body docs + web map title ("Assessed Value per Acre") are all accurate; only the **doc/project titles** ("Edmonton Revenue Per Acre" in `SPEC_phase1.md` + `ARCHITECTURE.md` headers) are a misnomer.
- Assessed value is a *biased proxy* for revenue: Edmonton's non-residential mill rate > residential, so value/acre understates commercial/industrial revenue pull.
- **`docs/SPEC_revenue.md` scopes the fix (next phase).** Key facts: the raw CSV ALREADY has the needed fields (`Tax Class` = clean 4-value field Residential/Non Residential/Other Residential/Farmland → use as mill-rate join key; `Assessment Class % 1/2/3` → split-class apportionment). Only EXTERNAL need is Edmonton's annual municipal mill rates (matching the assessment year). Formula: `levy = Σ_class assessed_value × (class%/100) × (mill_rate/1000)`, then `revenue_per_acre = total_revenue / area_acres`.
- **Open decisions in SPEC_revenue.md:** municipal-only vs total (municipal+education) tax; tax-exempt → $0 under revenue framing (real treatment change, currently flagged+included); year alignment; keep both metrics as a value-vs-revenue toggle?
- **Step 1 is "verify methodology vs reference projects"** — Peter is checking now. Strong Towns / Urban3 maps often headline *taxable assessed value* per acre (so current metric may already be a defensible convention); this check decides whether the next phase is a rename or a real new computation.

**deck.gl perf gotchas (in PERFORMANCE.md):**
- `wireframe: true` on extruded GeoJsonLayer = laggy (every triangulation edge). Never re-enable casually.
- `jointRounded`/`capRounded: true` on a PathLayer over detailed rings = HANGS (per-vertex triangle fans × ~89k vertices). Use miter (default).
- **Vertex count is the dominant render-cost lever** for the iGPU audience. The 45 m setback BUFFER *adds* vertices (rounded corners): raw boundary ~66k → post-setback ~89k → post-10m-simplify ~9.2k. This is why simplify must run last.

**Setback (unchanged, recap):** `_apply_setback` negative buffer in EPSG:3400, display-only, collapse fallback for slivers. Constant `SETBACK_CRS = "EPSG:3400"`, `SLIM_COLUMNS`.

**Key file locations:**
- `src/join_and_calculate.py` — join + `value_per_acre` + `export_geojson(result, output_path, crs="EPSG:4326", setback_m=0.0, simplify_tolerance_m=0.0)` + `_apply_setback` + `_apply_simplify` + `_count_vertices`.
