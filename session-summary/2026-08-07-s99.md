## 3. Technical Learnings

- ⚠️ **The relayed-brief failure mode has a SECOND class now.** S77 was invented
  *file names*; this session added an invented *repo asset* (the LRT buffer) **and
  a false claim about the EXTERNAL WORLD** (the ward geography) — the latter
  unfixable by grep, and it invalidated the brief's whole strategic angle.
  **Both rode in as parentheticals attached to well-formed "confirm whether X"
  questions.** The brief's explicit questions were sound; the damage came from
  unmarked assertions in the framing. Agreed fix (Peter, this session): **briefs
  carry an explicit "Premises I'm asserting — verify these" block**, tagged
  `[repo state]` vs `[external fact]`, rather than routing every brief through a
  pre-check round trip. **Risk is highest in a BUILD brief** ("build X using the
  existing Y"), where an invented Y gets built on instead of checked.
- **The $12 O&M half is deliberately NOT published, and this is the interesting
  decision.** $50/m/yr decomposes to $12 O&M + $38 renewal. Publishing $12 would
  put a **second recurring road number** beside `roadway_ops`' $4.635/m/yr —
  both annual, both non-capital, **~2.6× apart**, different sources. That is the
  arithmetically-true/descriptively-false collision `_two_bases` exists to
  prevent. **$38 renewal does not compete with $4.635 operating because they are
  not the same kind of number.** ⚠️ It is a **decomposition of basis (1), not a
  third basis** — never sum `roadway_renewal` with `roadway_om_renewal`.
- ⚠️ **$138.5M is a REQUIREMENT, not a GAP**, and this is the easiest way for the
  number to become wrong in someone else's hands. A gap is requirement minus
  what is already funded, and **this project has no funded-side data**. Do not
  set it beside a published citywide infrastructure-gap figure as though they
  were the same quantity. Stated in three places: the JSON block, `DATA.md` §13,
  and the tool's own printed header.
- **Also collector+local only** — arterials are excluded from `road_m_per_acre`,
  so every km and dollar **understates** the network. Revenue shown is the
  **municipal levy only** (education is provincial, excluded upstream in
  `apply_tax_rates`), which is the correct basis for a municipal levy question.
- **The 8 served/CSV name variants are harmless and deliberately NOT mapped.**
  `ANTHONY HENDAY SOUTH EAST` vs `…SOUTHEAST`, `PLACE LARUE` vs `PLACE LA RUE`,
  `RAPPERSWILL` vs `RAPPERSWIL`, etc. — they are **the same hoods that carry a
  null ward upstream**, so mapping them recovers nothing. 398/406 served hoods
  (98.0%) get a ward.

  recorded them as "not ours"; that is **wrong** and was copied forward four
