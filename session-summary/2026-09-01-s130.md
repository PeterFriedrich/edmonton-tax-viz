#### A. The busy stripe (#304)

`syncMoneyDetail` lights the clicked Detail button **active before the fetch
starts**, so the control read "done" while the map sat unchanged for a
multi-megabyte fetch. **The missing affordance was feedback, not speed.**

- An indeterminate sweep (`#moneydetail button.is-loading` + a `::after`
  gradient), set and cleared **inside `ensureGridData`** — the single choke point
  both call paths share, so the clear cannot leak down one of them.
- **Cleared on the fetch's own settle**, not after the caller's re-render: a
  failed fetch resolves (the `.catch`), so this is what stops a dead request
  stranding the stripe forever.
- `aria-busy` rides the same two writes. `prefers-reduced-motion` → static tint,
  matching `#loading-spinner`'s existing trade.

#### B. The prefetch (#305)

- **100 m warmed on idle from `hideLoading()`** via `requestIdleCallback`
  (1.2 s `setTimeout` fallback). ⚠️ **Not one step earlier** — `json()` parses on
  the **main thread**, and the boot's scarce resource is the GPU, not bandwidth.
  Hanging it off the overlay lift also means a **failed** load never prefetches
  (`failLoading` does not route through there).
- **50 m NOT pushed** (2.78 MB against a ~3.56 MB boot set). Warmed on
  `pointerenter`/`focus` of its own button instead.
- **Save-Data / 2g honoured for the UNSOLICITED warm only.** A pointer already on
  the button is a request, not a guess.
- ⚠️ **`loadGridData` (silent warm) was split out of `ensureGridData` (activate +
  indicate).** Only the latter may repoint `gridData`/`gridCell` — those are
  statements about what is **on screen**, and `applyView`'s
  `gridCell !== wantCell` gate reads them. A warm that set them would make the
  view believe a never-drawn grid was already up.
- The 50 m tooltip changed from *"fetched only when you pick it"* (which the
  hover warm makes false) to *"fetched only on demand"*.

## 3. Technical Learnings

### ⚠️ THE SESSION'S THEME: a "cannot be distinguished" caveat is not permanent

In #304 I recorded, in the verify file and the PR, that the busy stripe's gate
(`gridStore[cellM]` vs `gridFetches[cellM]`) **could not be falsified** — I wrote
an in-flight re-entry check specifically to separate them and it failed to,
because on re-entry the first call's stripe is still up, so the suppressed second
add changes nothing observable. Correct at the time, and recorded rather than
papered over.

**A few hours later the prefetch made it falsifiable.** The warm sets
`gridFetches[100]` *seconds* before `gridStore[100]`, so a click landing in that
window is a genuine wait the `gridFetches` gate reports nothing for. That check
now reds under the swap.

⚠️ **Rule: re-test parked "cannot be distinguished" notes when the system grows.**
A feature added later can create the very window that separates two options.
Saved to memory on [[check-where-the-value-can-be-wrong]].

### ⚠️ Four vacuous checks, all in tests I wrote the same session

Continuing S129's theme, and worse — these were not inherited, they were new:

1. `cleared` keyed on *any* class transition read **true under a build that never
   added the class**, because `classList.remove()` writes the class attribute
   regardless. Keyed on `on.length > 0` now.
2. `check(true, true)` printed beside the `waitForFunction` that was doing the
   actual work — a green line asserting nothing. Now reads the parsed cell count.
3. A whole-object comparison that **dumped 93k cells (2.8 MB) on failure**,
   burying every other line. `check` prints its operands — assert scalars.
4. The first falsification **crashed** the run (an unhandled `waitForFunction`
   timeout) instead of reddening a named check. A suite that dies on the first
   missing feature reports one defect and hides the rest — the prefetch waits now
   `.catch()` into a named check.

### The instrument matters as much as the assertion

⚠️ **Sampling the class between clicks could not have caught ANY of this.** Over
localhost the fetch settles in tens of ms, so a poll reads "not busy" whether the
stripe worked perfectly or was never written. `verify-grid-loading.js` records
class **transitions** with a `MutationObserver` installed before the first click,
and samples the `::after` pseudo **at the instant the class lands** — a right
class behind a wrong selector is an invisible control with green assertions
(falsified by renaming the CSS rule).

### The payload answer: Peter's assumption was right

| stage | 100 m | 50 m |
|---|---|---|
| transfer | **1.05 MB** gzip (2.83 MB raw) | **2.78 MB** gzip (7.63 MB raw) |
| `JSON.parse` | ~30 ms | ~90 ms (node, 3 runs, this box) |

**GitHub Pages already gzips** — confirmed `content-encoding: gzip`, 8,004,569 →
2,915,574 bytes. Trimming measured at **−7.0% / −6.4% gzip** for all three
candidates combined (drop `median_year_built`, coords to 5 dp, `exempt_frac` to
3 dp). 2.78 → 2.57 MB is imperceptible. ⚠️ **Do not re-open without a plan that
changes the FORMAT, not the contents** — quantised binary is the only thing in
the range of a 2–3× win, and that is a project.

⚠️ **`median_year_built` ships in both grids and `web/index.html` never reads
it** — absent from `ensureGridData`'s column map, though the pipeline fills it
89.9% / 92.6%. ~3% of payload. **Left in deliberately**: removing it is an
output-schema change (propose-first) and 3% is not a reason.

### Why the prefetch is nearly free

S129/S128's boot finding (`PERFORMANCE.md` 2026-08-30) is what makes it work:
**every byte is on the page by ~600 ms and the rest of boot is GPU shader
linking**, so the wire sits idle for seconds. The trap is that the *parse* is
main-thread — hence firing at the overlay lift, not during the GL window.
