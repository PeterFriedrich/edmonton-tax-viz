## 3. Technical Learnings
- **The full-revenue ÷ partial-cost honesty hazard is the crux of any coverage
  ratio here.** Property tax funds ALL city services; the modeled cost side is
  only roads+fire. So `revenue/svc_cost` reads ≫1 (median ~5.8×) NOT because
  land over-pays but because ~80% of the cost side is unmeasured. Any future
  "coverage/does-it-pay" framing (Lens C, debt lens) must carry this or it lies
  by omission. Locked as "magnitude, not break-even" (SPEC_utilities 3(b)).
- **The Services plane pattern is trivially extensible:** a new plane service =
  one `SERVICES` entry (`plane:{col,transform}`), one HTML `.svc` row, one
  `state.services` key, one tooltip fmt+row, one legend branch, one
  column-guard. `svcScale(col)` auto-honours the entry's transform for BOTH
  plane fill and legend. `servicePlaneLayer(col)` already shares ONE `svc-plane`
  (no z-fight).
- **`boundFmt` is the new seam for non-dollar ratio denominators** — the ratio
  legend previously hardcoded `"$"`. Any future dimensionless/non-$ denominator
  sets `boundFmt`; dollar ones omit it.
- **Column-guard idiom = graceful degradation for pipeline-ahead-of-data.**
  Every service checkbox + ratio button hides itself when its column is absent
  from the LOADED file, so shipping display code before the column is live has
  NO broken window — the control simply appears on the next refresh. This is
  why (a)+(b) could merge safely even though I built/verified against a local
  regen while live data (briefly) lacked the column.
- **Code-only-PR discipline (reaffirmed from S54):** `main.py --skip-png`
  regenerates `web/data/*` from the LOCAL raw snapshot (07-06), OLDER than the
  live auto-refreshed data. Pattern: regen → verify/screenshot on the real
  render → **`git checkout -- web/data/ output/`** → commit only code+docs. The
  new column reaches live via `SLIM_COLUMNS` on the next refresh (here it
  already had).
- **`gh pr edit` is STILL broken in this repo** (Projects-classic GraphQL).
  Workaround used again: `gh api -X PATCH
  repos/PeterFriedrich/edmonton-tax-viz/pulls/60 -f title=... -f body="$BODY"`.
- **Both halves went in ONE PR (#60), not two** — they both edit
  `web/index.html` and #60 was still open when (b) finished, so stacking a 2nd
  commit beat a conflict-prone split. "Staged" meant build-order, not
  necessarily PR-count. (Flagged to Peter; he merged as-is.)
- **Screenshot/verify harness quirk:** the `pkill -f "http.server 8931"` at the
  end of each run makes the Bash call exit **144 — harmless** (documented in
  prior handoffs). swiftshader needs ~20–60s settle per screenshot state.
