## 3. Technical Learnings

- ⚠️ **THE ONE TO KEEP — WORK STRANDED THREE TIMES IN THIS SESSION, and the
  rule against it was already written down twice.** Peter merged #189 while I
  kept pushing to its branch; the citation guard + tests sat on a dead branch
  for 40 minutes. Then #190 merged mid-build and stranded the *hook's own
  commit* — **the hook blocked it, and it was recovered with the hook's own
  printed instructions.** The lesson is not "remember harder": *"check the PR
  before committing"* fires **once, at the start**, and the danger is **every
  push after the merge**. Structurally, a remembered rule cannot cover a window
  that opens later. That is why it is now a hook.
- ⚠️ **`git log -S` alone cannot tell "drifted" from "never right"** — pair it
  with `git show <commit>:<doc>` at the authoring commit. Only the second is a
  citation *bug*; the first may just be a figure that moved. S102 used the first
  half only, which is how its §2 note came out backwards.
- ⚠️ **BAN line-number citations; do not validate them.** Validating one against
  the doc's current length encodes the bug. A line number fails **silently and
  plausibly** — it lands on other real content rather than erroring.
- ⚠️ **Two false positives shaped the citation parser, and both are pinned by
  tests:** `` `UI` `` is an **Urban Institution zone code** long before it is
  `UI.md` (short doc names now require the `.md`), and **`ARCHITECTURE.md Phase 2
  notes` is a project milestone, not a heading** — it had been resolving against
  `§2` by luck. Phases and sections are different namespaces.
- ⚠️ **A recovery instruction can lose your work.** The hook's first draft
  suggested `git cherry-pick A..HEAD`, which **silently excludes A**. It lists
  SHAs explicitly now.
- ⚠️ **A guard must fail OPEN when the cost of a false block is lost work.**
  The hook skips on missing `gh`/auth/network. On an ephemeral remote VM an
  unpushed commit is a lost commit.
- ⚠️ **The citation guard runs as a TEST, not a `refresh.yml` step** — it is a
  static repo check with no data dependency, and a docs typo must never red a
  good weekly data refresh and block a deploy of correct data.
- **`SPUR LINES` is a second unmatched name** ($0, 1 row), so
  `load_assessment.py`'s *"the lone remaining unmatched name"* is **correct only
  in scope** (the zero-value drop runs first). Left alone deliberately.
- **The 3 null hood names are NOT a silent drop** — `normalize_hood` does
  `fillna("")`, so they survive into the denominator and get reported. They are
  also why *"32 historical names"* reproduced (31 + the `""` bucket).
