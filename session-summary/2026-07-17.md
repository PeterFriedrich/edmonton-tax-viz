  `https://services.arcgis.com/B7ZrK1Hv4P1dsm9R/arcgis/rest/services/2026%20Property%20Tax%20Assessment/FeatureServer/0`
  — **esriGeometryPoint, 43,365 records**, `maxRecordCount: 1000` (so paginate

  Basement"), `meters`/`feet` (building size), `garage`/`firepl`/`bsmt`/`bdevl`

  **`latitude`**, **`parcelarea`** + `measured_in` (e.g. 3.2 "Acres" — LOT
  SIZE, already in acres for rural), `OBJECTID`, `GlobalID`.
- **CAUTION — likely RESIDENTIAL-ONLY / rural sample.** The building-attribute
  fields (garage/fireplace/basement/storeys) and the sampled records (all
  "RNG RD" rural addresses, 3-acre lots, one `bldg` per row) strongly suggest

  assessment roll like Edmonton's. **There is NO `tax class` / assessment-class
  field** — so we CANNOT decompose Strathcona levy by class the way we do
  Edmonton, and we cannot compute a `levy` at all (no mill rate in the data;
  the layer carries assessed *value*, not tax *revenue*). **This gap is the
  crux of the regional-lens design** (see Next Steps + the honesty note below).
- **GeoJSON pull works** via the ArcGIS REST `query` endpoint with
  `f=geojson` (or `f=json`); example count query:
  `.../FeatureServer/0/query?where=1%3D1&returnCountOnly=true&f=json` → 43365.
- **Also present:** `Rural_Subdivisions` FeatureServer (subdivision polygons —

## 3. Technical Learnings
- **The Glass grid pattern is now proven 3× (value/revenue/res).** Adding a
  cell metric = one `has_X` guard in `build_value_grid` ground path + one in
  `_cell_lot_metrics` eligible path + append to the payload column list + one
  entry in the web `gridData.columns` map. Everything downstream
  (`gridScale()`, render guard, legend, denominator toggle) is column-name
  generic — no per-metric web wiring.
- **Rounding bites synthetic grid tests.** A cell is ~2.47 acres, so a test
  `res_levy` of `1.0` rounds to **$0/acre** and fails a `> 0` assertion — the
  export rounds per-acre dollars to whole ints. Fix: use levy values ≥ ~1000
  in export-level tests (`test_export_res_columns_appended` uses 1000.0). The
  `build_value_grid`-level tests (pre-round floats) don't have this problem.
- **Strathcona (and most Alberta municipalities) publish via ArcGIS Hub, not
  Socrata.** Edmonton uses Socrata (`data.edmonton.ca/resource/<id>`);
  Strathcona uses ArcGIS Feature Services
  (`services.arcgis.com/<org>/arcgis/rest/services/<name>/FeatureServer/0/
  query`). Different pagination (`resultOffset`/`resultRecordCount`,
  `maxRecordCount` cap 1000), different format flag (`f=geojson`). A regional
  loader needs a second fetch path — don't assume the Edmonton `download_data.py`
  Socrata idiom transfers.
- **`gh pr edit` still broken** (Projects-classic GraphQL — S55/S56 learning);
  didn't need it this session (`gh pr create` was fine). `pkill http.server`
  exit 144 harmless; swiftshader ~2.5–4s settle per screenshot state.
