## 3. Technical Learnings
- **DON'T commit regenerated pipeline geojson in feature PRs that touch web code.**
  The weekly `refresh.yml` auto-commits a fresh `neighbourhood_value_per_acre.geojson`
  to master; any feature branch that also commits that file WILL conflict the
  moment the auto-refresh fires. The gate pattern (`state.hasPermitsPerAcre`, the
  `frac_commercial`/`new_units_per_acre` view gates) exists precisely so the web
  can ship WITHOUT the data — let the next refresh regenerate. This session's
  resolution (take `--theirs`, drop the geojson) is the general fix.
- **The units-vs-permits distinction is real and material** (not redundant):
  ABBOTTSFIELD 248 units / 2 permits; GARNEAU dense infill. Units = supply added;
  permits = project density / parcels touched. `new_permits_per_acre` max ≈ 2.84.
- **The Development web view = a `#denom`-style sub-metric picker is the house
  pattern** for per-view metric toggles (NOT the always-visible money `#toggle`
  panel, which is entangled with `state.metric`/`METRICS` and positioned by a
  fixed `top:`). Put per-view controls INSIDE `#layers` (like services/denom/
  ratio-denom/uses-prisms) and gate visibility in `applyView`.
- **`_devScale` must be keyed per column** once there are 2 metrics — a single
  cached clamp would show the units clamp on the permits ramp. Now `{[col]: {clamp}}`.
- **Auto-refresh commits to master mid-session** — `7ab7297` appeared while I
  worked. Always `git fetch` + check `origin/master` before assuming a PR is
