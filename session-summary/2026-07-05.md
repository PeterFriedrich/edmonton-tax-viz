  `[lon, lat, value_per_acre, revenue_per_acre]`, SW corners, cell

  `lon+0.00152 / lat+0.0009` reproduces cells exactly (used for the WEM
  verification).

  assessment CSV uses Title Case (`Account Number`, `Assessed Value`);
  property-info CSV is mixed (`Account Number`, but `lot_size`,
  `Latitude`) — a merge on stripped `Account Number` works; watch

  — re-add the carry-through (see `git show 70a5d54` / `6f41228`) as
  step one of the lot-acre variant.

  WEM and top-downtown cells, `lot_size.unique().sum()` gave sane parcel
  areas. Still unproven at residential condo towers (the 1,059-unit /
  1,051-null case, DATA.md §2) — the variant's validation pass must
  target those.
- **Grid-cell JSON compresses ~2.7:1 gz (473 KB from 1.29 MB) vs
  geojson's ~3–6:1** — dense numeric arrays gzip worse; remember when
  budgeting future web exports.
- **Socrata catalogue search endpoint** (`api.us.socrata.com/api/catalog/v1?domains=data.edmonton.ca&q=...`)
  works over **https** (http returns non-JSON) — handy for future
  dataset hunting.

  length), NOT response time. `response_code` letters (D 446k, AL, NF,

## 4. Technical Learnings (don't re-derive — these cost real time)

- **THE BIG ONE — validate display metrics at the display grain.** The
  first-draft dedupe rule (sum DISTINCT lot_size per point) passed the
  citywide/per-hood acreage bound test, then failed at cell level: townhouse
  complexes carry IDENTICAL apportioned shares (KAMEYOSEK: 309 units ×
  33.643 m² → distinct-sum 0.04 ac → fake **$1.2B/lot-acre** needle, 2×
  worse than the WEM artifact being fixed; also SOUTH TERWILLEGAR 171 ×
  149.547 m², CALLINGWOOD SOUTH). A citywide-aggregate error bound says
  nothing about a per-cell metric. Shipped rule = repeat-aware: repeated
  values < 1000 m² count PER UNIT (real shares), ≥ 1000 m² count ONCE
  (duplicated parcel). Threshold insensitive 500–2000 m² (rule-variant table
  in FINDINGS §4.3); "never dedupe" behaves identically on current data —
  the ≥1000 m² guard is cheap insurance. The hood bound test does NOT
  discriminate between rule variants; only the needle cells did.
- **PEMBINA is the one physical-bound violation** (1.41–1.47× under every
  rule): a 619-unit manufactured-home point claiming 96 lot-acres + 137
  Avenue lots whose deeded size crosses the hood boundary. Committed
  outlier; a NEW violation after a data refresh means the heuristic broke
  (check_lot_acre_bounds raises with hood names).
- **Property-info CSV column casing is mixed**: `lot_size`, `year_built`,
  `zoning` lowercase; `Account Number`, `Latitude` Title Case. usecols
  accordingly (bit me once).
- **scipy is NOT in the edmonton-tax env** — `df.corr(method="spearman")`
  raises ModuleNotFoundError; use pearson or add scipy.
- **Bash cwd persists between tool calls** — a pytest run silently found "no
  tests" because cwd was still `tools/profiling`. `cd` to repo root
  explicitly before test commands; and `kill %1` in a later shell does NOT
  kill a server started in an earlier one (job tables don't persist —
  the :8799 server survived and had to be killed by pid).
- **CSS-hidden-by-default panels need explicit display values on show** —
  `#denom { display: none }` in the stylesheet means setting
  `style.display = ""` re-hides it; set `"flex"`/`"block"` explicitly.
- **deck.gl data-identity caching**: lot mode filters the cells array; cache
  the filtered list per column (`gridData.cellsFor`) so moveend label
  re-culls diff to no-ops instead of re-tessellating 34k cells.
- **Validation numbers for regression sanity** (2025 data): lot-acre
  revenue p50/p97.5 = $28.0k/$105k (ground $18.0k/$144k); 79% of cells read
  higher under lot (lots exclude streets); top-10 lot cells all Downtown
  CBD; tower cell $14.8M revenue/lot-acre #1; WEM $12.6M ground → $290k lot.
