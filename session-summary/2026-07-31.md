## S81 — 3. Technical Learnings

**⚠️ NO VERIFY SCRIPT HAD EVER DRIVEN A REAL POINTER AT THE MAP — 26 of 26 call
`temporalClick()` / `openTemporal()` DIRECTLY in JS.** This is the most important
thing in this file. It is why single-tap-opens-everything survived the entire
temporal lens build unnoticed: **the gate under test lives between the gesture
and those functions**, so calling them directly proves nothing about a gesture.
The existing memory `verify-scripts-bypass-pointer-events` covered `.click()` on
*controls*; this is the same disease on the *map*, and worse, because the map has
no DOM element to click. `verify-peek.js` is the first script to use
`page.touchscreen.tap` / `page.mouse.click` against the canvas.

**⚠️ FOUR MEASUREMENT TRAPS, EACH OF WHICH LOOKS EXACTLY LIKE THE FEATURE BEING
BROKEN.** All four produced a full screen of red FAILs from working code. Recorded
in `MOBILE_USABILITY.md` §4 because the next mobile pass will hit them again.
1. **Deck renders its picking buffer ON DEMAND, and under headless SwiftShader
   that pass is too slow for a click's synchronous pick.** Bare taps registered
   **2 of 4**; with a `pickObject` issued first to warm the buffer, **4 of 4**,
   every one naming the right hood. ⚠️ **A harness artifact of software GL — NOT
   real-device behaviour. Do not "fix" the app for it.** The buffer can also go
   cold again in the CDP round-trip between warming and gesturing, which is why
   `gesture()` re-sends a gesture that should have changed state and provably did
   not (bounded at 3; it cannot manufacture a pass).
2. **A target pixel must pick the same hood across a RING around it, not merely
   pick something.** Click-time picking rounds device pixels differently from a
   manual `pickObject`, so a pixel on a polygon **edge** reports hood A and
   delivers hood B or nothing. Cost two wrong diagnoses: THE HAMPTONS at
   (405,540) passed twice then failed, and a tap on RAMSAY HEIGHTS peeked
   BRANDER GARDENS. Fix: same hood at ±8px in eight directions.
3. **`pickObject({radius: 2})` — the idiom every other script uses — reports a
   hood whose OWN pixel is empty.** In Money the prisms *are* the pickable
   surface (quirk w), so a set-aside hood has nothing under it and a real tap
   hits nothing. Use `radius: 0` when the point will be clicked for real.
4. **The west edge of the map at the default zoom is river-valley slivers** with
   no pixel far enough from a boundary to tap reliably. Scan from the middle.

**⚠️ A TOUCH TAP CAN DELIVER `temporalClick` TWICE** (touch event + compatibility
mouse event) — measured: mouse clicks toggled the card correctly while taps left
it stuck open, i.e. a close-then-open pair inside one tap. **I could not
determine from Playwright whether real iOS doubles the same way**, so rather than
debounce against a symptom I could not confirm, **every touch path was made
IDEMPOTENT**: `openPeek` no-ops when the hood is already shown, and
retap-to-unpin is restricted to pointers (`!noHover()`). Correctness no longer
depends on how many times the event fires. Same reasoning as S80's archive size
guard: an invariant that does not depend on the broken thing being right.

**THE SEAM IS `(hover: none)`, NOT `max-width` — and there are now TWO seams in
`web/styles.css`.** The ≤640px block is about **how much screen there is**; the
new block is about **what is pointing at it**. A finger needs a 44px target on an
800px tablet and a mouse does not need one in a 400px desktop window, so width is
the wrong test for both new rules. Measured on the real page: `(hover: none)`,
`(pointer: coarse)` and `(max-width: 640px)` are all true at 390×844 and all
false at 1440×900. ⚠️ **A blank-HTML test of these queries LIES** — with no
viewport meta, mobile emulation falls back to a 980px layout viewport and
`(max-width: 640px)` reports **false**. Test media queries against the real page.

**THE GATE IS ON THE WAY IN ONLY.** With panel mode already on, taps pin
directly — gating there would make pin-then-browse cost two taps a hood, and the
panel's own prompt says outright to tap a neighbourhood. So the gate applies
exactly to the auto-switch path Peter complained about.

**THE CARD DISMISSES ON AN EMPTY-MAP TAP — deliberately the OPPOSITE of
`#temporal`'s inertness rule.** That rule protects a surface you asked for from a
stray tap or the tail of a drag; this is a cheap preview that costs one tap to
bring back. Do not "make them consistent".

**PRIOR ART WAS CHECKED BEFORE THE DESIGN WAS OFFERED** (the standing
`check-convention-before-locking-design` habit). Google Maps, Apple Maps and
Zillow all go pin → small card → full sheet, and the shared reason is the one
that mattered: **the second target is a big card, not the small polygon that
opened it.** That killed the "tap the same hood twice" option, which puts stage
two back on a target you can miss.

**MEASUREMENT DROVE THE DESIGN, twice.**
- On a phone **the `.deck-tooltip` node never exists at all**, so there was no
  preview stage to gate — one had to be built. Peter's description ("you only
  the choice of tapping") was exactly right and stronger than stated.
- The × measured **20.3 × 21**, under half the 44px Apple HIG minimum (Material
  asks 48). "Twice as big" lands on the standard: it is now **44.5 × 44**, with
  `#temporal-name`'s `padding-right` widened to 46px to match. ⚠️ **The
  name/button overlap check must compare PADDING, not rects** — the name is a
  block div whose rect always spans the panel and always "overlaps" the button.

**SCREENSHOTS REVIEWED, not just the green banner** (the standing S78 lesson).
Both the card and the enlarged × render correctly at 390×844.
