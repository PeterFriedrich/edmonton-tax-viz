### 3b. ⚠️ A6 WAS FALSIFIED BY ONE COMMAND — THE ONE IT SAID IT HAD NOT RUN

A6 claimed superseded `DECISIONS.md` rows are "struck in place with a forward
pointer," generalising from **three grepped examples**. The sweep:

```
51 rows carry supersede/reverse/reopen language — 5 carry a strike. 6 in 280.
```

The mechanism is the opposite: the **new** row announces the supersession, the
**original is left unmarked**. Forward-only. A grep landing on a superseded
original gets no signal — L12's hazard exactly. **A6 HOLDS.**

The row's own text had flagged the sweep as unrun and named it "the verdict most
in the author's interest". It then cost one command. **Flagging a check is not
running it.**

### 3c. ⚠️ A NUMBER THAT FAVOURED MY OWN ARGUMENT WAS WRONG BY 3×, TWICE

  provably-closed mass is **46 KB (16%)**, and it is **relocatable, not
  prunable** (deleting closed sub-items out of live parents is A6 applied to

that-favour-me` earns its keep; the pattern is now three-deep in this repo.

### 3d. ⚠️ THE RETRIEVAL LOG CANNOT SEE BASH READS — AND THE BIAS RUNS THE WRONG WAY

The hook matches the `Read|Grep|Glob` **tools**. `bash grep`, `sed`, `cat`,
`python` are invisible. **The session auditing the instrument logged 4 reads
while consulting ~14 docs**; `DECISIONS.md` and `AUDIT_LEDGER.md` were both read
via Bash and both scored **zero**.

The undercount falls hardest on **large files a session greps rather than
opens** — which are exactly the prune targets. Rec #6 would have nominated
`DECISIONS.md` for deletion in a session that read it.

Fixed in #413 by printing the caveat **directly above the NEVER OPENED list**,
not only in the docstring — a warning the actor does not see is `_classify`
again. ⚠️ **Recs 1/2/6 rest on this table, so their ~2-week clock restarts from
2026-09-16, not from when the hook was installed.**
