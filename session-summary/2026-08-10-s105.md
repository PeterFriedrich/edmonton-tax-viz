**A. The architecture question, answered with measurements.**
**Adding lenses does NOT slow the site down.** Two mechanisms, both verified in
the source rather than assumed:
- **Lazy memoized fetch per lens** (`??=` guards) — an unopened lens is never

⚠️ **THE ONE COST THAT SCALES WITH LENS COUNT** is the served hood GeoJSON:

**B. PR #198 — the boot payload was half precision nobody could see. MERGED.**
GDAL was writing 15 digits. Two kwargs on the existing `to_file`:
`COORDINATE_PRECISION=5`, `SIGNIFICANT_FIGURES=6` → **340 KB → 166 KB gzip.**
- **Significant figures, not decimal places** — scale-invariant, so
  dollars-per-acre keep ~1 dp and fractions keep 6 with no per-column table.
- **6 not 3**: 3 breaks the 0.01 mix-shift comparison in
  `check_revenue_deltas.py` **and** re-renders S104's verified top lot-acre
  cells as 612.0 / 149.0 / 143.0 instead of **612.3 / 149.3 / 143.0**.
- 5 dp matches `WEB_PRECISION` already used by `load_roads`/`load_bike`/
  `load_zoning` — **this file was the only exporter not following it.**
- Rounding is **write-time only**; `export_geojson` still returns the
  full-precision frame (pinned by `test_export_returns_unrounded_frame`).

## 3. Technical Learnings

- ⚠️ **THE ONE TO KEEP: a merge that changes `web/data/**` does NOT deploy.**
  `deploy.yml` deliberately excludes `web/data/**` and `web/verified/**`
  (data normally arrives via `refresh.yml`, which deploys inside its own run).
  **A hand-regenerated data file arriving through a CODE PR is the case that
  exclusion does not cover**: #198 merged, master said 166 KB, and the live site
  kept serving 340 KB. It self-heals at the next weekly refresh, so nothing
  fails loudly. **Fix: `gh workflow run deploy.yml --ref master`** — the
  workflow provides `workflow_dispatch` for exactly this. **Verified by curl,
  not by the green run:** `content-length` 367,398 → **187,009**.
- ⚠️ **The weekly auto-refresh WILL conflict with any open PR touching
  `web/data/`.** It fired mid-session (`ec15370`) and rewrote every feature of
  the same file. **Resolve toward MASTER's data, never "ours"** — keeping ours
  silently reverts the site to the previous roll to preserve a formatting
  change. Re-apply the transform on top, importing the module's own constants
  rather than retyping them. Once merged the conflict cannot recur: the refresh
  pipeline now writes at the new precision itself.
- ⚠️ **`git checkout -- <file>` reverts YOUR change, not just the experiment,
  when you branched from a master that lacks it.** Falsifying the new precision
  test this way wiped the source edit; the next test run failed at *collection*
  (missing import), which is what surfaced it. The falsification itself was
  worth it — the test fails on the unrounded write, so it cannot pass vacuously.
- ⚠️ **Scale-invariant rounding is ACTIVELY WRONG on a year column.**
  `value_grid.json` carries `median_year_built` (max 2,026): 3 sig figs turns
  **1986 → 1990** and **2026 → 2030**. Nothing crashes; the age spikes just
  quietly lie. Any sig-fig pass needs a per-column exemption, which is most of
  why `value_grid` was rejected.
- ⚠️ **`value_grid.json` is MEASURED AND DELIBERATELY LEFT ALONE.** Largest
  payload on the site (930 KB over the wire) but only **16%** available
  (896 → 757 KB): values are already integers, coords already 6 dp, columnar
  transpose buys 4%. It is lazy-loaded so nobody pays it at boot, and it needs
  hand-written rounding rather than two kwargs. **Do not re-open** without
  reading `DECISIONS.md` 2026-08-09.
- **A guard that asserts an absence expires when the gap closes.** Five
  `verify-peek.js` checks encoded "Services has no panel". They were not
  protecting anything once the panel existed — but the *regression* underneath
  them was real, so the fix was to restate the invariant one level up
  (readout, not card) and cover both paths, not to delete the checks.
- **Rendering and screenshotting the panel caught a defect the checks could
  not** — "Roads + fire" wrapped to two lines at `width: 68px`. Widened to 82px
  with `white-space: nowrap`. No assertion would have failed.
- **Sum drift from 6 sig figs is $182 on $2.71B** (0.00001%), and nothing sums
  `total_revenue` client-side anyway — it renders through `fmtLevy` at 3
  significant figures. **We were storing 6 to display 3.**
- **Pages gzips `.geojson`** (`content-type: application/geo+json`,
  `content-encoding: gzip`) with `cache-control: max-age=600` — so repeat
  visitors re-pay the boot set every 10 minutes, which is what makes boot
  payload matter more than it looks.
- **`gzip -9` under-reports what Pages serves by ~13%** (324 KB vs 367 KB
  measured live). Local gzip numbers are a lower bound, not the served size.
