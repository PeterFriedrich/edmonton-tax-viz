every label would have needed a literal fallback anyway: **two sources of truth

`tests/test_window_labels.py` (4 tests): `WINDOWS` == the pins; both change

#### C. The weekly refresh broke on branch protection (#288, #289)

⚠️ **NOT a data failure — every guard passed and the GeoJSON regenerated.** The
push to `master` was refused:

```
GH006: Protected branch update failed for refs/heads/master.
- Required status check "test" is expected.
```

**Cause:** `master` gained a required `test` status check between 2026-08-25 (last
green refresh) and 2026-08-31. A commit pushed straight to `master` carries no

`github-actions` bot because `gh secret list` was **empty**: `HEARTBEAT_TOKEN`
had never been set and `refresh.yml:48` silently fell back to `github.token`.

**Fix:** Peter created a fine-grained PAT (Contents: R/W, this repo, ~366d) and
set `HEARTBEAT_TOKEN`. Protection is `enforce_admins: false`, so his pushes
bypass the required check while PR merges stay gated.

## 3. Technical Learnings

### Measure the exposure before accepting the audit's framing
Twice this session a filed item described a wider defect than existed. F4's
"proper fix" was worse than the cheap one once the async fetch was measured; T8's
"latent trap" had no consumer, because the number it corrupted never left the
pipeline. **Both were reframed by reading the actual data path, not the item.**
This is the third session running that TODO items have lagged reality.

### An aggregate nothing consumes is deleted, not corrected
`frac_nonres` carried a real contradiction for two months and it never mattered,
because nothing read it. Correcting the sum would have preserved a column with no
consumer; deleting it removed the contradiction and the maintenance both.

### A guard may halt the pipeline only if the pipeline cannot trip it
The rule that let `test_window_labels.py` gate the refresh, where the CODEMAP
staleness test was refused: **both sides are hand-edited constants**, so it can
only fail inside a PR that bumped one and not the other. The same test also
decided `check_unclassified_zoning` goes in the *digest* rather than the refresh
— the thing it watches is drawn honestly, so it is a go-look signal.

### A fallback makes a missing dependency silent
`secrets.HEARTBEAT_TOKEN || github.token` ran as the bot for months. The
surrounding comments carefully reject `git push || true` because an EXPIRED token
would report green — but nothing caught the secret being **ABSENT**. Same
silence, different cause, one step removed. Now a TODO item (propose-first).

### Two push failures that look alike and are not
- `GH006 ... protected branch hook declined` → auth SUCCEEDED, protection
  declined. Identity problem.
- `! [rejected] ... (fetch first)` → stale base. Says **nothing** about the token.
- An **expired** PAT is a third thing: 403, not `GH006`.

### Environment quirks (this box) — all still true
- ⚠️ **`pkill` in a chain returns 144 and aborts it.** Hit twice this session.
- ⚠️ **`pgrep -f "pattern"` matches its OWN command line** — a `| wc -l` of 1 or
  2 after killing a server is the shell matching itself, not a survivor.
- ⚠️ **Playwright lives in `tools/profiling/node_modules`** — `/tmp` scripts
  cannot `require('playwright')`.
- ⚠️ **No GPU (SwiftShader).** Never read an absolute render/boot timing here.
- ⚠️ System `python` is 3.6.8 — use `.venv/bin/python`. `cd` first; a bare
  `.venv/bin/python` from another cwd fails.
- ⚠️ **8 orphaned `http.server` processes** from past sessions (ports 8777, 8778,
  8790, 8791, 8792, 8796, 8797, 8842). Flagged to Peter, **left alone** — not
  cleaned up. One holds a shell from a dead session.
