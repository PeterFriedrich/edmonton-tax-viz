**Audit fix #1 — name-correction ordering bug (commit `c2c77f2` on `master`):**
- **Bug:** `NAME_CORRECTIONS` dict was applied in `join_and_calculate.py` AFTER aggregation. Aggregation grouped on uncorrected names, so if two raw names collapse to one boundary name (e.g. `"CHAPPELLE AREA"` + `"CHAPPELLE"`), they aggregated separately, then the correction renamed one, producing TWO rows with the same name → duplicate polygon at the merge + un-summed values.
- **Fix:** moved `NAME_CORRECTIONS` (the 8-entry dict) into `src/load_assessment.py`, applied right after name normalization (`df["neighbourhood_name"] = df["neighbourhood_name"].replace(NAME_CORRECTIONS)`), BEFORE aggregation. `join_and_calculate.py` no longer mutates names (`agg = assessment`, no `.copy()` needed since it only reads now).
- **Tests:** removed now-misplaced `test_name_correction_applied` from `tests/test_join_and_calculate.py`; added `test_applies_name_correction` and `test_corrected_names_aggregate_together` (the regression test — feeds both `"CHAPPELLE AREA"` and `"CHAPPELLE"`, asserts one summed row of $500k) to `tests/test_load_assessment.py`. That test imports `aggregate_by_neighbourhood` too.

## 4. Technical Learnings

**Sniff-test results (run this session, not saved to any file — reproduce via the script in Restoration if needed):**
- `value_per_acre` over 405 neighbourhoods: median **$1.73M**, mean $1.77M, max **$13.78M** (Downtown), max/median = 8.0x.
- Percentiles: 10th=$39K, 25th=$1.08M, 75th=$2.32M, 90th=$3.11M, 95th=$3.63M, 99th=$5.40M.
- **Three-part distribution:** (a) near-zero tail ~bottom 10% (parks/highways/undeveloped), (b) dense mid-band $1.08M–$3.63M where most neighbourhoods cluster (~3.3x spread), (c) a few spikes up to Downtown.
- **Top 12:** DOWNTOWN ($13.78M), WÎHKWÊNTÔWIN ($9.78M), GARNEAU, SUMMERLEA (West Edmonton Mall — big commercial value/contained footprint), UNIVERSITY OF ALBERTA, BOYLE STREET, STRATHCONA, WINDSOR PARK, MAGRATH HEIGHTS, MACTAGGART, WESTMOUNT, BELGRAVIA — all dense central or big-commercial. Correct.
- **Bottom 12:** MILL WOODS GOLF COURSE ($173), RIVER VALLEY KENDAL, multiple ANTHONY HENDAY * (ring-road corridors), RIVER VALLEY * (parkland), EDMONTON SOUTH WEST / ENERGY AND TECHNOLOGY PARK (undeveloped fringe). Correct — tiny value over large area.
- **Metric-sanity confirmation:** Glenora is NOT top-12. It's wealthy but low-density (big lots), so per-acre it's mid-pack. Confirms the metric rewards density, not raw wealth — working as intended.

**Phase 2 elevation decision (informed by the above):** Use **linear `getElevation`** for the first cut — Downtown's spike IS the story and it's honest; the park/highway tail flat on the ground is also correct. The mid-band will compress (same washout as the PNG, but vertical). Add a log/sqrt transform toggle as easy follow-up if mid-band nuance matters. Decision rationale: don't need to discover the distribution shape live during Phase 2.

**Decision — did NOT polish the Phase 1 matplotlib colorscale.** The quantile/log colorscale fix flagged in the 2026-05-27 handoff was deliberately SKIPPED because it's matplotlib-specific throwaway work — deck.gl sets its own color/elevation ramps in JS.
