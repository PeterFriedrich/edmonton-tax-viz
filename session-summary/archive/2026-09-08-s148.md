## 3. Technical Learnings

### R5 — `check_revenue_deltas.load_committed` (#366)

`load_committed` returned `None` on **any** non-zero `git show`, so a rev that
does not resolve, a missing git, a non-checkout and a corrupt blob all shared one
exit path with the legitimate case — exit 0, `flagged=0`, *"first publish"*. The
guard printed the all-clear over **406 neighbourhoods it had never compared**.
Reproduced: `--rev deadbeef` against the live served file.

`None` now means exactly one thing: `git cat-file -e` missed the object **and**
`git rev-parse --verify` confirms the rev resolves. Everything else raises
`BaselineUnavailable`.

⚠️ **The finding's proposed fix — "a distinct WARNING line" — would not have been
enough, and the script's own docstring says why:** a warning inside a green run
reaches nobody, which is the whole reason the flagged path files an issue. So a
fault takes that channel: `flagged=fault` plus a fault-shaped body, through the
`refresh.yml` step already gated on `flagged` being neither `'0'` nor `''`.
**No workflow file changed.** ⚠️ **On that path the value is not a count.**

Also retired: a `--geojson` outside the repo raised `ValueError` out of
`relative_to` — a traceback and a **non-zero exit** from the one guard that must
never stop a publish.

⚠️ **Tests drive `main()` against a REAL temporary git checkout** with `ROOT`
monkeypatched. What is under test *is* the git invocation and how its failures
are classified, so a stubbed subprocess would assert the stub.

### R4(5) — the reference-layers CRS path (#368)

⚠️ **THE FINDING WAS HALF WRONG AND THE CORRECTION IS THE POINT.** Re-measured
before building (the `todo-can-lag-executed-work` rule earning its keep):

| mutation | result |
|---|---|
| `WORKING_EPSG = 999999` (as recorded by the audit) | **3 tests already fail** — but *incidentally*: they exercise the highway path, `.to_crs` raises `CRSError`, they crash. **A crash is not a measurement.** |
| `WORKING_EPSG = 4326` | **843 green.** The dangerous one. |

4326 exists, so nothing raises — and the module is metres throughout
(`MARGIN_M` 60 km, `RIVER_SIMPLIFY_M` 25 m, `HIGHWAY_SIMPLIFY_M` 30 m,
`BOUNDARY_SIMPLIFY_M` 100 m), all silently becoming **degrees**. A 25° simplify
tolerance is ~2,800 km; the river flattens and the file still writes. **The hole
was a VALID-but-wrong CRS, not a missing one.**

⚠️ **Two traps, both of which would have produced a test that passes under the
bug.** (1) The stubs build in 4326 and **reproject to `WORKING_EPSG`, the same
last step the real fetchers take** — a stub hard-coding metre coordinates feeds
`build()` honest metres regardless of the constant. (2) **An output-is-lon/lat
assertion does NOT catch 4326**: the final `to_crs(4326)` is a no-op, so the
coordinates come out lon/lat anyway. What does not survive is the **SHAPE**.

⚠️ **The property tests pass on ANY metre-based CRS** — EPSG:3776 left all 847
green. Hence the literal 3400 pin, stated as a **consistency** pin, not a
correctness one (3400 is hardcoded across `src/`; there is no constant to import).

### Method notes that generalise

- ⚠️ **`sys.path` carries BOTH `.` and `scripts/`, so `import generate_status` and
  `import scripts.generate_status` are DIFFERENT module objects.** The first draft
  of the year-constants OK-direction test monkeypatched the wrong one and the
  patch **silently did nothing**. Read constants off the module the code under
  test actually imports. Verified with `generate_status is scripts.generate_status`
  → `False`.
- ⚠️ **`0 or fallback` / dead escape hatches:** `check_doc_citations.py`'s bare-name
  check has a `"/" not in name` clause that **can never fire** — the regex class is
  `[\w.-]`, so `name` never contains `/`. It clearly means to exempt path-form
  citations and cannot. **Worked around, not fixed** (see §4).
- **`_FakeResp` in `tests/test_vintage_report.py` grew `raise_for_status`** so an
  HTTP error reaches a check as an exception rather than a parsed error body.
- ⚠️ **Suite counts in a commit message go stale when the branch is rebased.**
  "832 → 838" was written pre-rebase off a 827-test master; the true figure after
  rebasing onto #366 is **832 → 843**. Amended before pushing. **Measure both
  sides at push time, not at build time.**
