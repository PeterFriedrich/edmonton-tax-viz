## 3. Technical Learnings

### ⚠️ Verify a relayed dataset by IDENTITY, not by existence
`HTTP 200` + a matching name proves the ID is real, not that it is *new*. Pull
the column list, the row count, the year span, and **two totals**, and compare
against what is already catalogued. Here all four matched exactly.

### ⚠️ A viewport-fit assertion is not a collision assertion
Two boxes both anchored to the viewport bottom overlap by a **constant**, so the
bug is invisible at every height and a `y + height <= viewportHeight` check
passes throughout. Assert clearance **against the specific element**, at several
heights. The project's own docs already framed this correctly for the Services
panel (*"measure the TRACK, not the row"*) — same class of error.

### ⚠️ `#botleft` paints THROUGH left-column panels
Everything on the map is `z-index: 1`, so paint order falls back to DOM order
and `#botleft` (compass, `Center 2D/3D`, legend) draws over anything earlier.
`#about.open` solves it with `z-index: 5`; **a tall left-column readout must not
copy that** — it buries the legend. Cap the height instead.

### Socrata query notes (`data.edmonton.ca`)
- `$select=col,sum(budget) as b&$group=col&$order=b DESC` works; **sums come
  back as STRINGS** — `float()` them or `f"{x:,.0f}"` raises `ValueError:
  Unknown format code 'f' for object of type 'str'`.
- `curl -G --data-urlencode` mangled the `$where` clauses; a small
  `urllib.request` + `urllib.parse.urlencode` script was reliable.
- Metadata (incl. `rowsUpdatedAt`) is at `/api/views/<id>.json`, data at
  `/resource/<id>.json`.
