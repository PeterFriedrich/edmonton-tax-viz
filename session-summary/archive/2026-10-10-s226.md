## 3. Technical Learnings
- **Phone seam specificity trap:** the phone rule `#controls > div { max-width: 100% }`
  has specificity (1,0,1). It beats `#optpanel` (1,0,0) but loses to
  `#optpanel[data-view=…]` (1,1,0). Any attribute- or class-qualified `#optpanel`
  width rule must therefore be wrapped in `@media (min-width: 641px)`.
- **The CSS can now target the panel by view:** `#optpanel[data-view="<button>"]`
  is the hook for any per-view panel rule.
- **Measured width = cap + 2px:** the border adds 2px, so the 289 cap measures 291
  and the 260 cap measures 262.
- **Probe pattern that worked:** serve `web/` with
  `.venv/bin/python -m http.server 8811 --directory web` and md5-check the root.
  Put the probe in the scratchpad and run it with
  `NODE_PATH=/home/opc/edmonton-tax-viz/tools/profiling/node_modules`. Use
  `chromium.launchServer()` and `srv.kill()`. Stop the server by its saved pid.
  ⚠️ `browser.process()` does not exist on a launched Browser.
- **The width override is a quick preview:** injecting a
  `<style>#optpanel{max-width:Npx !important}</style>` previews widths without
  editing the repo. This box lacks the site's fonts, so text renders 15–20% wider
  and wrapping looks worse than on a real browser.
