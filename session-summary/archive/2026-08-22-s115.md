#### B. The fix — `far` is null, not zero (`754d409`)

`gross_area` is null/zero on ~6.2% of rows; `build_hood_lot_acres` summed it with

Now: null and zero masked together, `.sum(min_count=1)`. **16 of 410 hoods go
null** (12 already set-aside grey, 4 newly off-scale, 1 residential).

## 3. Technical Learnings

### ⚠️ A GUARD CAN BE DOING A SECOND JOB NOBODY WROTE DOWN
The asymmetric residential gate is documented purely as a land-use filter. It is
*also* the only thing that kept a 6.2% data gap off the opportunity end — 67 of
69 affected hoods are barred by it for an unrelated stated reason. **The lens was
clean by luck of overlap, not by design.** Before porting a guard to a finer
grain, ask what it is *actually* filtering, not what its comment says.

### ⚠️ AN AGGREGATE UNIT CAN HIDE A DEFECT ENTIRELY
Every problem above exists at hood grain too and is invisible there: `NaN → 0`
across ~400 properties barely moves a FAR; one acreage is diluted; every hood has
some activity so `z(activity)` behaves. **The re-grain was the diagnostic.**
Sister to S112's *"a finer rendering audits the aggregate"* — this time the finer
rendering was never built and the *measurement alone* did it.

### ⚠️ CHECK THE PIPELINE'S OWN FILTERS BEFORE PROTOTYPING ITS METRIC
My first activity prototype showed a single **−119-unit demolition** dominating
the whole opportunity end via the kernel. That was **my script missing
`NEW_WORK_TYPES`**, not a defect. Refiltered, it matched the shipped grid to
0.7%. **Import the pipeline's constants; don't re-derive its semantics.**

### ⚠️ DON'T WRITE A PREDICTION INTO A SPEC
I amended `SPEC_development.md` with *"WESTVIEW VILLAGE still saturates"* before
checking — the clamp is recomputed over a changed population, so it was a
prediction. Measured afterwards: it held (and became #1). **It was right by luck;
the measurement is what made it a claim.**

### THE CITATION GUARD CATCHES `DATA.md: <number>` IN CODE COMMENTS
`# ... (DATA.md: 27,202 rows, ~6.2%)` failed `check_doc_citations.py` as a
line-number citation. Reword to `DATA.md counts them together (~6.2% of rows)`.
