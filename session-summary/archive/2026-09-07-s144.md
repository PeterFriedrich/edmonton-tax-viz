### PR #350 — the rate re-scope

`roadway_ops` **$4.635 → $9.32/m/yr**, maintenance half **$1,285 → $5,970/km**
(FY2017 `Roadway Maintenance`, $65,671,000 ÷ ~11,000 km).

- ⚠️ **The argument that decided it was not in the audit.**
  `data/city_budget_context.json` **already published that $65,671,000 program
  figure**, so the repo was rejecting $1,285 in the budget pod while shipping it
  as half of a public map layer. Found by grepping, not by reading the audit.
- ⚠️ **The findings doc's objection to swapping — the arterial blend — is a
  caveat the SNOW half of the same rate already carried.** That is what made it
  a price rather than a blocker.
- **The map does not change by one pixel.** `scaleT` is
  `value / quantile(vals, 0.975)`, so a uniform scalar cancels exactly. Only
  legend numbers, panel percentages and copy move. **Re-derive this before
  assuming any rate change is visible.**
- **`check_cost_copy.py` named both stale claims instantly**, including
  *eleven times → five times*, which is stated **in words in three places** and
  which no per-rate row could see.
- ⚠️ **The regeneration carried an incidental one-day upstream refresh** — local
  `data/raw/` is a coherent 2026-09-03 pull against the 09-02 raw behind the
  committed data. One withdrawn CHAPPELLE permit (1408 → 1407) and ~18 bytes of
  geometry. **Kept rather than isolated**: reverting `dev_grid.json` alone would
  leave it showing 09-02 permits while the neighbourhood file shows 09-03.
  **Check `ls -la data/raw/` vintages before any regeneration and say what moved.**

### ⚠️ Method notes that generalise

- **An audit's findings are claims to reproduce, not a task list.** The S142
  brief named documents that did not say what it said they said — **twice**
  (§6 and §7.1). Both were caught by reproducing, not executing.
- **Falsify your own instrument.** This run's guard-classifying regex returned
  `?` for most entries; its totals were **dropped, not published**. A
  `verify-peek` "timeout" was a 150 s cap against a **219 s** run.
- ⚠️ **`pgrep -f <name>` / `pkill -f <name>` matched this session's own tooling
  THREE times** — once `pkill -9 -f pubsweep.sh` **killed the shell that was
  about to write the next sweep script**, because that shell's command line
  contained the string. **Check running processes with
  `ps -eo pid,cmd --no-headers | grep "[p]attern"`, never bare `pgrep -f`.**
  Memory `pgrep-watchers-match-themselves` updated with a **second mechanism**:
  `until grep -q "<sentinel>" <file>` waiters whose files **exist** but whose
  sentinel was never written — one hung 55 days on a job that **succeeded**.
- **10 orphaned watcher shells found** (12–56 days). **2 killed; 8 remain** —
  the classifier blocked the batch kill. Command in §4.

### Environment quirks hit this session

- ⚠️ **A full 42-script sweep against the PUBLIC build is impractically slow** —
  scripts written for `/full/` hit the 300 s timeout there; ~1 script per 6 min.
  **Use a bounded subset with a ~150 s cap**, and expect `verify-peek.js` to need
  **>219 s** legitimately.
- The normal sweep against `:8777` takes **~35–40 min** serially.
- Build both builds and confirm `/proc/<pid>/cwd` before believing a 200.
