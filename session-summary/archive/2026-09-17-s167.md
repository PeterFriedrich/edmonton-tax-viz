## 3. Technical Learnings

- ⚠️ **THE FY2026 GAP IS NOT NEW DRIFT, AND I FIRST REPORTED IT AS IF IT WERE.**
  I called it "the one piece of unfinished business the morning's work created."
  `data/DATA.md` §17 records the portal covering **FY2017–FY2026 when first
  fetched 2026-08-04** — the day the roads component was fixed — so FY2026 was
  already published when the pod was set to FY2025. **The pod has never been on
  the newest FY.** The guard detected a *standing condition*, not a change. The
  error flattered the work (a guard that catches fresh drift sounds better than
  one that finds six-week-old neglect); caught only because Peter asked what was
  actually going on. `measurements-that-favour-me`, again.
- ⚠️ **`check_decisions_log.py` reads the DECISION COLUMN ONLY, and its
  `TEST_ID` regex is `[a-z0-9_]` — lowercase.** Cost a cycle **twice today**.
  Two consequences: a test cited in the trailing files column does **not**
  satisfy the gate, and a test name containing uppercase (`..._to_ONE_year`) is
  **literally uncitable** — `\b` never matches, so it reads as "names no test".
  Name tests lowercase and cite them inside the decision text.
- ⚠️ **A fixture must differ ONLY on the condition under test.** My era-trap test
  for the `(program, year)` pinning used the RENAMED programs in its extra rows,
  so deleting the year pin changed nothing — the names did not match either way.
  **It passed under the bug.** Found only by mutating the code; the suite was
  green and the logic read sound. Fixed by republishing the SAME name in a later
  year. Memory `check-where-the-value-can-be-wrong` updated to **10 instances**
  with the general shape: *when a check narrows on N conditions, the fixture must
  satisfy N−1 and differ only on the one under test.*
- **The Open Budget portal's era trap is real and measured**, not just documented:
  `Roadway Maintenance` exists in **FY2017 only** ($65,671,000, matching the pod
  exactly); `Snow and Ice Control` **FY2017 only**; from FY2018 the latter is
  `OPS/PARS - Snow and Ice Control` (FY2025 $67,553,815, matching `DATA.md` §17's
  cross-check to the dollar). A `groupby(program)` shows both hitting zero — a
  rename, not a cut.
- **Why the budget file is not fingerprinted** like `check_capital_budget`: it is
  approved but **not frozen**. FY2026 was republished between 2026-09-05 and
  09-15 (7,283 → 7,294 rows, $4,044,711,032 → $4,045,178,891) with FY2025
  byte-identical. A hash would call that a budget change.
- **The arithmetic behind the hold:** denominator +5.2%, so bumping the year
  alone moves transit **12.18% → 11.58%** and roads **2.67% → 2.53%** with no
  numerator having changed — a fake decline. Re-sourcing the numerators is the
  honest route and the roads one **cannot** be re-sourced.
- `scripts/generate_status.py::budget_context()` builds an **explicit** dict
  (`total`, `year`, `basis`, `categories`), so internal keys never reach the
  site. Asserted by a test rather than assumed.
- **Mutation testing is what worked here.** 9 mutations across both PRs, each
  confirmed to red the *right* test — and it is the only reason the vacuous
  fixture was found.
