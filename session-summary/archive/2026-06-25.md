## 4. Technical Learnings

**Setback mechanics (`_apply_setback` in `src/join_and_calculate.py`):**
- Negative buffer MUST happen in a projected metric CRS (EPSG:3400) — buffering in 4326 degrees would be wrong. The helper reprojects to `SETBACK_CRS`, buffers `-setback_m`, then `export_geojson` reprojects the result to the target `crs`.
- Collapse detection: `shrunk.is_empty | ~shrunk.is_valid`; collapsed rows fall back via `shrunk.where(~collapsed, metric.geometry)`. Tested with a 5m-wide sliver + 20m setback → falls back to original (area ~500 m²), logs "collapsed".
- **It's display-only** — this is the key honesty point; recorded in ARCHITECTURE.md. Do not let anyone think the shrunk geometry is the real boundary.

**Outline / performance gotcha (IMPORTANT):**
- `wireframe: true` on extruded `GeoJsonLayer` = laggy with 405 polygons (renders every internal triangulation edge). DO NOT re-enable it casually.
- `stroked: true` (footprint ring only) is the cheap alternative — outlines sit at ground level, not the top of each tower. For flat/low neighbourhoods this is identical; for tall ones the setback gap does the visual separation instead.
- If tower-TOP outlines are ever wanted without wireframe cost: a separate thin top-cap layer (not yet built; flagged as more complexity).

**Spike-emphasis is an OPEN design question (recorded in ARCHITECTURE.md, "do NOT implement until chosen"):**
- User wants high-value districts to stand out more vs the mid-band. A *global* `ELEVATION_SCALE` increase raises everything proportionally (honest, but won't separate the top). Only a **super-linear transform** (`value^k`, k>1) actually pulls spikes away — but that EXAGGERATES (k=2 → a 2× district looks ~4× taller), conflicting with the Phase-1 "linear is honest" decision. Held for later. Options noted: mild k≈1.3–1.5 + legend disclosure, vs keep-linear-and-solve-crowding-via-zoom+setback.

**Deferred (bundled, recorded in ARCHITECTURE.md):** User wants the **zoom-out (~10.2 → ~9.4)** bundled with a **proportional `ELEVATION_SCALE` bump** (uniform global multiplier — honest, NOT the power curve above), tuned together against the zoomed-out view. NOT yet applied.

**EPSG:3400 vs 26911 (came up re: the audit skill):** Edmonton ≈ 113.5°W sits at the eastern edge of UTM Zone 11N (120°–114°W) → elevated distortion there. EPSG:3400 (NAD83 / Alberta 10-TM Forest) is a single province-wide zone, central meridian 115°W, Edmonton ~1.5° off it — low distortion + it's the official Alberta standard. Pipeline already uses 3400 everywhere; skill now flags 26911 as an inconsistency.
