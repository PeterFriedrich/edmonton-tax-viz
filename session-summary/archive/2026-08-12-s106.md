## 3. Technical Learnings

### ⚠️ THE ONE NUMBER THAT SHAPES THE BREAK-EVEN WORK
Computed this session from the served file + `data/city_budget_context.json`:

| | |
|---|---|
| revenue modelled | **$2,715M** |
| cost modelled (operating basis) | **$473M** = **12.3%** of the $3,846M tax-supported operating budget |
| **implied verdict if built today** | **every hood runs a 5.7× surplus** |
| unmodelled | **$3,372M** has no per-hood model at all |

**Not an uncertain answer — a wrong one, wrong by roughly the same factor everywhere**,
which is what would make it look plausible. Hence: **coverage is the product, not a
caveat.**

### ⚠️ THE BASIS TRAP (the silent killer for any composite cost number)
| basis | rate | includes | feeds |
|---|---|---|---|
| **lifecycle** | **$50**/road-m/yr | O&M + renewal over a 50-yr life | `svc_cost_per_acre` |
| **operating** | **$4.635**/road-m/yr | maintenance + snow, **no capital** | `transport_cost_ops_per_acre` |

**Same metres, 10.79×.** Both ship in the same served GeoJSON — the `_ops` suffix is
load-bearing. **Two distinct rules people conflate:**
- Never **mix bases** ($50 with $4.635).
- Never sum **`roadway_renewal` ($38) with `roadway_om_renewal` ($50)** — that is not
  basis mixing, it is **double-counting renewal** ($50 = $12 O&M + $38 renewal).

### ⚠️ THE `driver_scope` RULE (new, from review — SPEC §2b)
A cost may only be distributed by a local count when the service is **consumed where
it is supplied**. Register entries declare `site_bound` | `network_shared`; only
`site_bound` is allocated per hood.

| term | driver | scope |
|---|---|---|
| fire | dispatches at the address | `site_bound` ✅ |
| stormwater | impervious area | `site_bound` ✅ |
| roads | local+collector metres (arterials already excluded) | `site_bound` ✅ |
| **transit** | scheduled departures at stops in the hood | **`network_shared`** ⚠️ |

⚠️ **The arterial exclusion (2026-07-01) was already this rule, found by instinct
before it had a name.** ⚠️ **The reviewer's prescription ("exclude the non-residential
share") is OVER-BROAD** and would corrupt the three correct terms — the axis is
site-bound vs network-shared, **not** residential vs non-residential.

### ⚠️ WHAT WE DO NOT HAVE (checked, not assumed)
**No population and no employment per hood, anywhere.** `new_dwelling_units` is a
**flow from permits, not a stock**; "employment" appears only as a *zoning category
label*; the dwelling model water/franchise share is **internal, never emitted per
hood**. So any per-capita allocation is blocked on an ingest that does not exist.

(~$1.8M/acre) and printed it under a title saying *Revenue* — consistent arithmetic,
labelled wrong, no visible symptom. Fixed **structurally** (own `state.labCut`), not
with a guard.
