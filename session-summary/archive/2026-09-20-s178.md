## 3. Technical Learnings

- ⚠️ **PETER'S PUSHBACK IMPROVED THE ANSWER, AND CHECKING PRIOR ART SETTLED
  IT.** He asked for *"something like 'near zero'"* instead of `<0.01`. I had
  recommended `<0.01%` **without checking what the file already does** — and
  `fmtMix` (`:4677`) already floors at `<0.1%` with a comment that states his
  own reasoning almost verbatim: *"a category that earned a row should not then
  claim to contribute nothing."* Plus `money0` → `<$1` and `fmtSvcRatio`. So
  the house idiom is `<X`, **three times over**, and "near zero" would have
  been a fourth idiom for a solved problem. **`check-convention-before-locking-
  design`: I should have cited the prior art before recommending, not after he
  pushed.** My `<0.01%` was right but under-checked — `fmtMix` floors at one
  decimal, `fmtPct` renders two, so it is the same rule scaled.
- ⚠️ **FALSIFICATION CAUGHT A BUG IN MY OWN CHECK, AND IT LOOKED LIKE A CODE
  DEFECT.** `verify-infill.js` first reported a real-looking failure
  (`"0.00 new permits / acre (0 permits, 2023–2025)"` in Blue Quill). The cause
  was mine: the window-picker test **upstream in the same script** leaves
  `state.devWindow` on `3yr`, and I had filtered on the **5yr** rate column
  against a **3yr** count. `check-where-the-value-can-be-wrong` — the fixture
  must differ only on the condition under test. Fixed by reading columns off
  the page's own maps for the window in state.
- ⚠️ **A CONSTANT'S WIDENING IS INVISIBLE TO THE OBVIOUS CHECKS.** Both natural
  checks (no nonzero prints `0.00`; no true zero prints the floor) pass when the
  floor is set **100× too wide** — nothing renders `0.00` and no true zero
  floors, while `0.4998` silently prints `<0.01%`. This is the
  `MIN_PIECE_M`/`WEB_MIN_PART_M` lesson in a new place: **the check that matters
  is that the boundary matches the rounding boundary.** Found by mutating, not
  by reasoning.
- ⚠️ **MY FIRST FAR MEASUREMENT WAS WRONG IN THE DIRECTION OF MY HYPOTHESIS.**
  I divided by **ground** acres and got implied floor areas of **0.01 m²** —
  physically impossible, a dead ringer for the bike artefact story I was
  pattern-matching to. FAR divides by **deduped lot area** (`export_value_grid.py`
  `out["far"] = gross / lot_m2`); recomputing via `parcel_frac` gives **17.7 m²
  minimum** and kills the finding. `measurements-that-favour-me`: **decompose a
  number that supports your own conclusion before reporting it.** I caught this
  by checking the definition before claiming, which is the only reason it did
  not ship.
- **`includes()` is a weak assertion on pluralised text.** `"1 permit"` is a
  substring of `"1 permits"`, so the count check **passes on a broken plural** —
  proved by mutation. The separate plural check is not redundant; a comment now
  says why.
- **Count-based metrics have a decisive artefact test that length-based ones
  lack.** Bike needed distribution analysis; `fmtDev` just needed the numerator
  column — every one of 378 rows had an integer ≥ 1, settling it in one query.
  **Look for the numerator before measuring the distribution.**
- **Confirm the file you measure.** The local `web/data/neighbourhood_value_per_acre.geojson`
  and the live `peterfriedrich.github.io` copy were **md5-identical**, which is
  what licensed measuring locally (`confirm-the-server-you-measure`).
- **The `/full/` build does not exist in `web/`.** `verify-smoke.js` documents
  two URLs, but `http://localhost:8931/full/index.html` **404s against the dev
  server** — the dev server *is* the full build ("quirk rrr"). To test both
  roots, run `scripts/build_site.py --src web --out <dir>` and serve that.
  ⚠️ **Worth doing whenever `web/index.html` changes** — I added comments, and a
  comment is what tripped `build_site`'s base-tag guard and broke the #117
  deploy.
- **Playwright lives in `tools/profiling/node_modules`.** A probe script must
  sit in `tools/profiling/` or `require('playwright')` fails. Entering Infill
  needs `#views button[data-view="development"]` then
  `#devmode button[data-devmode="infill"]` — there is no top-level Infill button.
