## 3. Technical Learnings

### 3a. ⚠️ THE PROBE REPORTED "INVARIANT" FOUR TIMES WITHOUT LOOKING

This is the session's real finding, and it happened in a script written
**specifically to hunt readouts that do not respond**. Each failure was green,
plausible, and produced a full clean-looking table.

| # | the probe did | reported | why it could not vary |
|---|---|---|---|
| 1 | `features.find(f => f.properties.name === HOOD)` | tooltip + peek invariant in **all 13 rows** | the field is `neighbourhood_name`; `f` was always `undefined` |
| 2 | `String(viewTooltip({object: f}))` | tooltip invariant in all 13 rows, **second time** | `viewTooltip` returns deck's `{ html }` **wrapper**; `String()` on it is a constant `"[object Object]"` |
| 3 | `innerText` on `#peek` | peek invariant everywhere | `#peek` is CSS-gated on `(hover: none)`; **`innerText` returns `''` for a hidden element, `textContent` reads it** |
| 4 | captured `#budget` *after* calling `openTemporal` | `#budget-pod` reaches nothing, **in all six views** | the pod yields the left column to `#temporal`, so **the probe's own readout-opening closed the surface it then measured** |

⚠️ **#4 is the one to carry forward: the instrument mutated the state it was
measuring.** A probe that opens panels in order to read them is not a passive
observer of a UI whose surfaces contend for space. The fix was capture *order*
(hoist the budget read above `openTemporal`) plus closing `#temporal` at the end
of each capture so it cannot poison the next one.

**The script now prints a `selftest` line per readout** and flags empty values,
`THREW:`, `(no feature)` and `[object Object]`. ⚠️ **A `DEAD` selftest line
invalidates every `.` in that column** — it does not weaken the measurement, it
removes it.

This is `check-where-the-value-can-be-wrong` for the 8th and 9th time, and the
**third brief running** to need its own falsification pass before its output
meant anything.

### 3b. The measured matrix — no control reaches nothing; the finding is one column

15 control groups × 6 views × 9 readouts, full build, 1440×900. After the four
instrument fixes, **every control reaches something.** All findings are `panel`:

| control | panel | note |
|---|:---:|---|
| `services / services` (10 rows) | **.** | the F1 defect — 6 other readouts follow the picker |
| `development / devwindow` | **.** | but `#devmode` **and** `#devmetric` both reach it |
| `money / revcut` | **.** | but `#metric-row`, the level above it, reaches it |
| `lab / labcut` | **.** | the same three cuts as `#revcut` |

⚠️ **Invariance is a CANDIDATE, not a verdict** — `#coloradj` is *supposed* to
leave the title alone. The audit's second pass is judgement: *what relationship
did the layout promise?* Adjacency in one panel, a shared caption or a picker
sitting directly above a readout are promises; distance is not.

### 3c. T1 — the Services panel defect, reconfirmed by a method that wasn't aimed at it

S157 found it by driving `SERVICES` keys deliberately. This probe reached the
same cell **without being pointed at it**, which is the argument for sweeping the
class rather than fixing the instance. `renderServiceCost` reads the fixed
`SVC_COST_BASES`, never the picker. **3 of the 10 rows are public.**

### 3d. T4 — `#budget-pod`'s state class and rendered pod disagree (measured, not inferred)

```
before            {"body":"mills",        "disp":"none"}
after click       {"body":"mills budget", "disp":"flex"}
after openTemporal{"body":"mills budget", "disp":"none"}
```

`body.budget` stays set over a `display:none` pod. **Consequence: the reader's
next press toggles the class off an already-invisible pod, so restoring it takes
two presses.** `CONTROLS_MATRIX.md` §3 says the mill-rates yield uses a CSS
sibling selector *"rather than a JS toggle, so the two cannot both think they own
the slot"* — ⚠️ **here they do.** Open question: was the budget yield ever decided,
or merely inherited from the mill-rates rule?

### 3e. ⚠️ T5 is NOT a cleared row — it is a probe limitation

`moneydetail` / `devdetail` read invariant on tooltip and peek **only because the
probe feeds a HOOD feature to `viewTooltip` in grid modes too**, and the grid
modes have their own cell-grain tooltip. Same class as 3a #1. Recorded in the
brief §4 and `TODO.md` explicitly so a later run does not score it as clean.

### 3f. The class's own precedent was already written in this repo

`CONTROLS_MATRIX.md` §5.6 (closed 2026-07-27) says: *"if a control ignores the
pickers around it, it is probably a lens, not a detail mode."* **Read backwards,
that sentence is this brief:** if a *readout* ignores the pickers around it, the
reader has been told a relationship that does not exist.
