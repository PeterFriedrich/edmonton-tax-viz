⚠️ **THE BRIEF'S STACK WAS WRONG AND IT MATTERED.** It specified pmtiles served

#### D. ⚠️⚠️ THE RETRACTION (#268) — and how it was caught

#267's comments claimed an `idle`-gated lift costs **~5.6s** and a raced 500ms
floor is starved to **5433ms**. **Both figures are wrong.**

**How it was caught:** falsifying the new verify script by reintroducing the
defect — **and the test passed.** The defect does not cost 5 seconds. Earlier
probes had left Chromium processes alive on this 4-core box, and the contention
manufactured the numbers.

Clean re-measurement, three runs each on an idle box:

| variant | fade start |
|---|---|
| **shipped** (render gate + remainder floor) | **549 / 560 / 568ms** |
| `idle` gate | 1045 / 1091 / 1045ms |
| raced 500ms floor | 1049 / 1066 / 1132ms |

**The design choice survived; the story told about it did not.** ~500ms, not
~5s. Comments and `DECISIONS.md` now carry the corrected figures.

#### E. The verify script (#268)

`tools/profiling/verify-loading-overlay.js`, 19 checks. **Asserts the
MECHANISM, not a clock reading**: a millisecond ceiling cannot separate 568ms
from 1045ms without flaking under load, but **an idle-gated lift lands within a
millisecond of an idle event and a render-gated one does not** — that holds on
any machine. Falsified against both defects; the shipped build passes on repeat
runs.

⚠️ **Its first version went green while testing nothing** — the idle array was

the element on `window`), while the MapLibre instance is a top-level `const`
visible only to a bare identifier. A **vacuity guard** now fails loudly rather
than letting the real check pass on an empty set.

## 3. Technical Learnings

### A wrong millisecond is more dangerous than a wrong pass/fail
The `run-verify-scripts-alone` rule was known and I still broke it — because I
applied it to *pass/fail* and not to *measurements*. A red gets investigated; a
bad number gets written into a commit message as justification. **Before
trusting any timing off this box: `ps aux | grep -c "[c]hrome"`, check
`/proc/loadavg`, take 3 runs.** Memory updated.

### Falsifying the test is what caught it
The regression test passed against the deliberately reintroduced defect. Had I
skipped falsification — the test was green on the real build — the wrong
numbers would have shipped as settled fact. **S123 learned to falsify against
the defect rather than the signature; this session shows falsification also
audits the CLAIM the test was built to defend.**

### ⚠️ This box cannot check anything that depends on glyph width
`fc-list : family` returns **three families**: Cantarell, DejaVu Sans Mono,
Fixed — **none of the CSS stack**, so `sans-serif` falls back to MONO and every
text width reads **~15–20% long**. I started tuning `max-width` against that
before catching it. Geometry that does not depend on glyphs (positions, hit
targets, z-order, `pointer-events`) is still fine to measure here. Saved as
memory `oracle-box-has-no-web-fonts`.

### Polling an animation perturbs it
The first overlay probe polled `getComputedStyle` every 100ms and reported a
lift at 9154ms. A `MutationObserver` on the same page: ~570ms. **A probe that
runs on the main thread competes with the thing it measures.**

### The verify "suite" is a convention, not a harness
38 `verify-*.js`, **no runner, no `npm test`**, and only `verify-smoke.js` is
wired into a workflow (`refresh.yml`, both builds). The shape is not uniform:
**34 use `process.exit(fail ? 1 : 0)`, only 23 print `ALL CHECKS PASSED`** — the
rest are diagnostic printers that always exit 0. ⚠️ **A batch runner that greps
for the banner reports those as failures**; mine did, on `verify-labels.js`.
Now documented in `ARCHITECTURE.md`.

### Deliberately NOT wired into CI, and why
`verify-loading-overlay.js` stays manual. `refresh.yml` is the *data publish* —
it would gate a data refresh on a UI regression. `tests.yml` is the right gate
but is deliberately offline and browser-free, so it would need Chromium
installed on every PR (~1–2 min) to guard a path touched roughly never.

### Environment quirks (this box) — all still true
- ⚠️ **Playwright lives in `tools/profiling/node_modules`** — a script in `/tmp`
  cannot `require('playwright')`. Hit again this session.
- ⚠️ **Use a fresh port**; stale `http.server` processes squat across sessions.
- ⚠️ **Run verify scripts ONE AT A TIME** — and see the timing caveat above.
- ⚠️ System `python` is 3.6.8 — use `.venv/bin/python`.
