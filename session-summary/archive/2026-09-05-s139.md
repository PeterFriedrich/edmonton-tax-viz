## 3. Technical Learnings

### ⚠️ THE FINDING — a shipped public rate is contradicted 4.65× by the City's own budget

**Full record: `docs/FINDINGS_roadway_maintenance_rate.md`. PR #335.**

`roadway_ops` ($4.635/m/yr, feeds the public `cost_roads_ops_per_acre`) is built
on **$1,285/km maintenance + $3,350/km snow**. The City's published **FY2017
`Roadway Maintenance` program is $65,671,000** — and it is a **SEPARATE program
from `Snow and Ice Control` ($63,709,000)**, so it is maintenance-only and the
right comparator in kind, with no snow double-count.

**$65,671,000 ÷ 11,000 km = $5,970/km — 4.65× the $1,285.**

✅ **This largely explains the "2.6× gap" open since 2026-09-02:**

| maintenance half | operating all-in | gap vs $12/m/yr lifecycle O&M |
|---|---|---|
| **$1,285** (as shipped) | **$4.635/m/yr** | **2.59×** |
| $5,970 (published FY2017) | $9.32/m/yr | **1.29×** |
| $7,974 (× branch growth 1.336 to 2025) | $11.32/m/yr | **1.06×** |

**The two sources do not disagree about roads.** The open item's premise does
not survive.

⚠️ **NOT NAIVELY SWAPPABLE — three blockers, two structural:** $5,970/km is a
citywide blend **including arterials** (which cost more per km than locals) so
it would **overstate** collector+local metres — the same mismatch
`denominator_mismatch` already flags for snow, and restricting to locals
**re-widens** the gap; the comparison mixes a citywide blend against a
*neighbourhood*-specific $12 either way; and FY2017 is the only year with a
roads-only program.

⚠️ **WHAT $1,285 ACTUALLY MEASURES IS STILL UNKNOWN.** The article gives it no
denominator and no scope, and **no clean decomposition of the published program
reproduces it** (materials-only $1,634/km is closest, still 1.27× off). **Do not
invent a scope for it.**

### ⚠️ `claude remote-control` (subcommand) ≠ `claude --remote-control` (flag)

Verified against the CLI binary (2.1.258) — this matters for any future
remote-control session that needs launch flags:

- **`claude remote-control` (subcommand)** — what tmux session `cc` has run since
  2026-07-07 (child worker still on **2.1.235**). Matched at
  `t[0]==="remote-control"` and routed to the bridge chunk **before the normal
  option parser**, then spawns a separate `--print --sdk-url … --session-id cse_…`
  child whose argv the bridge builds. **`--disallowed-tools` has no path in.**
  ⚠️ Running `claude remote-control --help` **starts a session** rather than
  printing help — it hung and had to be killed.
- **`claude --remote-control [name]` (flag)** — ordinary interactive option set
  (beside `--bare`, `--brief`); `remoteControl` / `remoteControlName` are threaded
  into the same options object as `modelCli`, `permissionModeCli`, `tools`. **One
  process, full option parsing, flags hold.**
- ⚠️ **Honest limit, and the setup prompt makes Sonnet test it:** the running
  child's bare argv is not a controlled test — its parent had no such flags
  either. Structural evidence only.
- `--remote-control` optionally consumes the next token, so **put it last and
  quote its name**; use the **comma form** `--disallowed-tools Agent,Task` when
  another flag follows (it is variadic).
