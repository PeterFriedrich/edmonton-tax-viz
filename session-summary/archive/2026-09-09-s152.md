### ⚠️ THIS SESSION'S SUBAGENTS WERE FORCED TO HAIKU, AND THE FIX IS A MEASUREMENT

```
CLAUDE_CODE_SUBAGENT_MODEL=claude-haiku-4-5-20251001
CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1
CLAUDE_CODE_CHILD_SESSION=1       # + CLAUDE_CODE_BRIDGE_SESSION_ID
```

`_FORCE` (added **2.1.257**, per the binary's own changelog) makes this
**unoverridable** — the code deletes the `model` parameter from the Task tool's
schema (`FORCE ? t.omit({model:!0}) : t`). `CLAUDE_CODE_SUBAGENT_MODEL`'s
precedence changed at **2.1.251**. **Neither var is in any `settings.json`,
`~/.bashrc` or `~/.profile` — grepped, absent** — so the harness sets them and
**this is a launch property, not a repo fact: re-measure, never quote.**
Also true here: **no `Agent`/`Task` tool was exposed at all**
(`ToolSearch("select:Task,Agent")` → nothing), so delegation was impossible.

`fable-session` item said both vars were unset *"so nothing is pinned"*. Rewritten

answer, because the two states want opposite advice.

### ⚠️ `pkill -f` KILLS THE SHELL THAT RAN IT — AND IT COST TWO TOOL CALLS

`pkill -f 'grep -ao'` ended the whole Bash-tool shell (**exit 144**, no output).
`pkill` excludes *itself* but **not its ancestors**, and `-f` matches the full
command line — which for the enclosing `bash -c "pkill -f 'grep -ao'; …rest…"`
contains the pattern literally. Proven both directions with a unique marker; one
run showed **both at once** (inner shell printed `SURVIVED`, outer died at 144
because the marker was still literal in *its* line). **Kill by PID.** Silent AND
destructive: exit 144 with no stderr reads like the *investigated* command failed.
