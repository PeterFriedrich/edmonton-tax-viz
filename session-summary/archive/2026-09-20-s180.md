**(b) THE FIX — wrap code, scroll tables.** Both shipped, both verified live.

- **Code wraps** (`white-space: pre-wrap; overflow-wrap: break-word`).
  ⚠️ **Not a scroller:** `overflow-x` on a `display: table-cell` box is
  unreliable, and a nested horizontal scroll region is a poor touch affordance.
- **Tables scroll** (`display: block; width: max-content; max-width: 100%;
  overflow-x: auto`) — ⚠️ **wrapping a dataframe destroys what it is showing.**
  As a block-level scroller it stays *inside* the clipping parent, so the
  `overflow: hidden` ancestor never bites.
- ⚠️ **A hanging indent to mark wrapped continuations was tried and REMOVED.**
  The whole cell is one `<pre>`, so `text-indent` reaches only its first line —
  it cost 2.5em of width at 390px and marked nothing. The before/after
  screenshots were pixel-identical, which is what proved it inert.
- **Verified reachable, not merely unflagged:** the fixed table's
  `maxScrollLeft` is **112px — exactly the amount previously lost.**

## 3. Technical Learnings

- ⚠️ **AN ASSERTION PLACED WHERE THE VALUE CANNOT BE WRONG PASSES UNDER THE
  BUG — instance 11, and this time it SHIPPED.** I checked
  `.jp-OutputArea-output`, its `table` and its `pre`; the clipping lives on
  `.jp-OutputArea-child`, their parent. All three children were honestly
  0/24 overflowing. **`check-where-the-value-can-be-wrong`. Falsify by name:
  ask which element could *hold* the defect, not which one is convenient to
  query.**
- ⚠️ **A CSS DECLARATION CAN BE INERT, AND COMPUTED STYLE STILL REPORTS IT.**
  `.jp-RenderedHTMLCommon` carries `overflow-x: auto` on a `display: table-row`
  box. `getComputedStyle` says `auto`; nothing scrolls. **This is also why the
  template looks like it already handles wide output — it declares the fix it
  does not apply.**
- ⚠️ **`overflow: hidden` IS PROGRAMMATICALLY SCROLLABLE.** Setting `scrollLeft`
  moves a hidden container even though no reader can. **A movement test alone
  inverts the answer on exactly the elements under suspicion.** Reader-
  reachability = computed `auto`/`scroll` **AND** observed movement.
- ⚠️ **AN INLINE ELEMENT'S `getBoundingClientRect()` IS A UNION ACROSS ITS LINE
  BOXES.** A wrapped `<span>` reports a rect wider than any line it occupies
  and looks like overflow. **Use `getClientRects()`, or measure containers.**
- ⚠️ **A GREEN INSTRUMENT PROVES NOTHING WITHOUT A POSITIVE CONTROL.** Two
  probe versions printed "OK — nothing clipped" against pages I had *already
  measured* as clipped 112px. **The live pre-fix pages were the control that
  caught both.** Keep an un-fixed artifact reachable while building the check.
- ⚠️ **`git checkout -- <path>` WIPED AN UNCOMMITTED FIX, AGAIN.** Restoring
  after a mutation test reverted the notebook HTML to the *committed* (first-
  fix) state, so the next run measured the table rule's absence and the guard
  stayed red. **`commit-before-falsifying`. Re-run the injector, don't
  re-checkout.**
- ⚠️ **A DEFECT INVISIBLE AT THE AUTHORING WIDTH SHIPS FIVE TIMES.** The reports
  were rendered and reviewed at desktop width, where the clip is exactly 0/54.
  **`finer-rendering-audits-the-aggregate`, inverted: a NARROWER rendering
  audits the wider one.**
- ⚠️ **Playwright lives in `tools/profiling/node_modules`** — a probe script run
  from the scratchpad dies with `Cannot find module 'playwright'`. **The script
  must live in `tools/profiling/`.** (Already in S179's handoff; hit it again.)
