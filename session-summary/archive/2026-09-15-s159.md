### 3b. ⚠️ THE VERIFY SCRIPT WAS WRITTEN RED, MERGED RED, AND FALSIFIED BOTH WAYS

`verify-services-panel.js` landed in #398 with **30 preconditions green and 7
checks red** against the broken build. Then a one-line mutation printing the
driver's label flipped all 7 green (10 distinct renderings), and it went red again
on the reverted build.

⚠️ **Do this for every guard.** A check written after the fix is green on arrival
and has never been shown capable of going red.

⚠️ **Two vacuity traps found while writing it, both of which would have produced a
green check under the bug:**
1. *"The panel names the selected service"* is **vacuous for 7 of 10 layers** —
   the panel already prints "Roads", "Transit", "Bike" as row labels. Only
   **storm, fire, water** can distinguish a panel that followed the picker. Those
   three carry the naming claim.
2. Ground truth is read from the **served geojson first** (4 cost columns, 4
   distinct values at DOWNTOWN: 912 / 170 / 35,200 / 330), so identical panels can
   never be blamed on the data.

### 3c. ⚠️ SERVICES IS NOT A PICKER — the locked decision was written against a control that does not exist

### 3h. Environment quirks

- ⚠️ **`page.screenshot` times out at the 30 s default on this app** — the deck.gl
  canvas never settles. The repo's own working pattern is
  `{ timeout: 90000, animations: 'disabled', caret: 'initial' }`
  (`shot-click.js`). Element-level `.screenshot()` fails the same way; use a
  **clipped page screenshot** from a measured bounding box.
- ⚠️ **PR creation hit `HTTP 503` from the GitHub GraphQL API once**; a retry
  5 s later succeeded. The branch had already pushed — **do not re-push, just
  re-run `gh pr create`.**
- ⚠️ **Restart the http server before EVERY Playwright run** — it wedges and then
  serves empty responses while still answering 200.
- **`.venv/bin/python` is relative** — a heredoc after `cd tools/profiling` fails
  with `No such file or directory`. Use an absolute path or `cd` back first.
