## 3. Technical Learnings

### ⚠️ THE SESSION'S THEME: a check placed where the value cannot be wrong
**Three instances, one session.** Saved to memory as
`check-where-the-value-can-be-wrong`.

1. `verify-glass-cell.js` asserted the landing default **after clicking the
   button that SETS it** — passed with the default pinned to 50.
2. The same file checked the colour clamp **only after returning to the
   resolution that seeded the cache** — where a stale cache is indistinguishable
   from a fresh one. **The shipped 4× bug passed it.**
3. `test_build_rejects_source_with_existing_base` expects `SystemExit` and its
   fixture had no `BUILD_STAMP` literal — it would have passed on the **new
   guard firing first**, never reaching the base check it exists to test. That
   file warns about this exact shape one test earlier.

**Rule:** ask *where is this value most likely wrong?* and assert there; then
falsify and confirm **that named check** reds. ⚠️ **A falsification that fails
via a different assertion than predicted is a finding** — bug (4) below reddened
"infill pins the default", not the check I expected.

### ⚠️ Three performance conclusions died to the next measurement
Each was stated with reasonable confidence and then overturned:

| stated | killed by | now |
|---|---|---|
| 50 m costs **3.7%** fps | taller viewport | **10.3%** — cost scales with pixels |
| load complaint "confirmed, mostly network" | rerun on same machine | **withdrawn** |
| GPU "unknown but Intel-ish" | `about:support` | **Iris Xe integrated; RTX `Active: No`** |

- **n=1 vs ~900 samples in one table.** The fps rows aggregate ~900 frames over
  8 s; **every load row is n=1**. The same machine read `domInteractive` **800
  then 409 ms** — a spread wider than the between-machine gap being explained,
  and 409 is *faster* than the old laptop's 481. **A number's sample size is
  part of the number.**
- **Frame rate is meaningless without its pixel count.** 668,880 px → 3.7%;
  1,083,214 px → 10.3%. Marginal frame time **0.274 → 0.981 ms (3.6×) for 1.62×
  pixels** while the 100 m baseline grew only 1.18×. Superlinear because a
  taller viewport shows **more cells**, not just more pixels per cell.
  **Standing rule: record `devicePx total` beside every fps figure.**
- **The sanitised WebGL string was WRONG ABOUT THE PART**, not merely vague:
  it read `Intel(R) HD Graphics`; the adapter is **Iris Xe**, much later and
  faster. Refusing it was right for a stronger reason than expected.
- ⚠️ **My capture instructions caused two of these.** "Dock devtools at the
  BOTTOM" held the *wrong variable* constant (matching dock position while
  halving viewport height is two different measurements, not one made twice).
  And asking for `about:support` → "Description" asks for the **first** block —
  exactly the field that cannot reveal an idle discrete card. **The decisive
  fact was an `Active:` flag I never asked for**; Peter pasted everything anyway.

### The 50 m grid's standing cost
**10.3% of frame rate for 2.69× the cells, on integrated Iris Xe at 1.08M device
px.** Acceptable for an opt-in lazy layer that starts unselected — **not free**,
as 3.7% implied. Fullscreen is 1.91× those pixels and plausibly worse, but
**that is arithmetic, not a measurement.** The site has **no discrete-GPU
measurement at all**.

(rolls yearly vs code's several times a week), and it is **async**, landing
after first render. **A build number is read off a broken page**, so it must be
present the instant the page is. Reuses `build_site.py`'s existing
`DEFAULT_BUILD` rewrite pattern — no new mechanism. `GITHUB_SHA` → `git
rev-parse` → `"dev"`, failing **open** (a missing git binary is not a reason to
refuse to publish).
