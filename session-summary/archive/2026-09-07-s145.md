## 3. Technical Learnings

### PR #354 — V1: the fix was the HAYSTACK, not the match

`check_cost_copy.py` tested `expected in html` against the raw 432,532-char
file. **Reproduced first:** roads blurb reverted to the retired `$1,285` + one
ordinary comment carrying `$5,970` → **all 7 rates reported OK, exit 0**.

- **New `prose()`** builds the search space from two **derived** (not
  enumerated) sources, so new copy is in scope automatically: (1) the HTML's
  visible text — `<script>` blocks, `<!-- -->` comments and tags removed, which
  carries the `#about-*` methods-pod paragraphs; (2) every **line-anchored**
  `blurb:` string literal. **Haystack is now 4% of the file** (16,912 chars).
- ⚠️ **Concatenation must be joined SEAMLESSLY.** The lifecycle rate is written
  `"... $50 per metre " + "per year, ..."` — a separator between literals hides
  a claim the reader plainly sees. Sources are newline-joined so a match cannot
  be manufactured across the seam between two unrelated blurbs.
- ⚠️ **Comments are excluded BY CONSTRUCTION — nothing strips them from the JS,
  and that was deliberate.** The obvious fix (a comment-stripping lexer) would
  have to resolve regex-vs-division correctly: `web/index.html` has `//` inside
  **5 string literals** and a regex literal containing **both** quote characters
  (`.replace(/[&<>"']/g, ...)`). A haystack that never reads comments cannot get
  that wrong. Same reason the `blurb:` key is **line-anchored**: `// Uses
  blurb: ...` prose appears **three times** in the real file.
- **Accounting that looked wrong and wasn't:** `_blurb_texts` finds **19**
  blurbs against 27 `blurb:` grep hits. 27 − 3 (inside comments) − 5 (`null`)
  = 19. My first probe asserted 22 and was the thing in error.
- **Deliberate cost, in the docstring:** a rate quoted only in a dynamic builder
  (`servicesBlurb()`, `changeBlurb()`) or in `temporal-note`'s `textContent` now
  **fails**. Safe direction. **Widen `prose()`, never loosen the match.**
- **`tests/test_check_cost_copy.py` — the guard had NO test file; it has 13.**
  ⚠️ **Falsified against 4 mutations of the fix:** raw-file haystack reds
  **6 by name**; a space between concatenated literals reds 2; dropping the line
  anchor reds 1; joining sources without a separator reds 1. A first test pins
  that the fixture still produces the figures the others key on, so a claim
  rename cannot make them pass vacuously.

### PR #355 — V4: the reds were the SMALLER half

All four misbehaviours reproduced against the built public page before editing.

- ⚠️ **The finding the audit did not have.** `click` in these scripts is
  `page.$eval(sel, b => b.click())`, a **JS click that ignores visibility**. So
  after failing its row check, `verify-transit.js` **kept going and passed 23
  further checks against a UI the public cannot reach** — a false green nested
  inside a red run. The exit code alone could never surface it.
- **BUILD gates** (`verify-transit.js`, `verify-ind-permits.js`): each reads
  `FULL_BUILD` and asserts **both directions** — `shown === fullBuild`, not
  `shown`. The old form could only fail one way; the new one also fails if the
  public build ever starts **showing** a full-only control.
- ⚠️ **Keep the DATA gate first and SEPARATE.** A missing column hides the row
  on **both** builds (`web/index.html` ~line 7193 onward), so reachability alone
  conflates "old data file" with "public build" and misdiagnoses. Order:
  column → build.
- `verify-ind-permits.js`'s public branch ran only **1** check; it gained the
  assertion its sibling had — the hidden button must not still be the **active**
  metric. A hidden control still colouring the map is the bike-row defect.
- **PARTIAL/COMPLETE:** 14 early exits across 10 scripts print
  `PARTIAL — ran N checks, then stopped: <reason>`; those 10 print
  `COMPLETE — ran N checks`. ⚠️ **Consumers key on `PARTIAL`** — the other 32
  scripts print neither, so *absence* of PARTIAL is the passing condition.
- ⚠️ **4 scripts (`ind-permits`, `nonres-revenue`, `res-revenue`, `peek`) count
  only `fail`** — no `pass` variable. `${pass + fail}` threw `ReferenceError` at
  runtime; they needed a `ran` counter. **`node --check` does not catch this** —
  it is a runtime scope error, not a syntax error. Only running them did.
- **The both-builds sweep, which nothing had ever run: 20/20 exit 0.**
  `/full/` **10 of 10 COMPLETE**; public **6 COMPLETE + 4 correctly PARTIAL**
  (`bike` 3, `transport-cost` 5, `transit` 4, `ind-permits` 2).
- ⚠️ **Both new gates FALSIFIED, not merely observed passing.** Patching the
  **built** public page to leak the full-only controls (`if (!FULL_BUILD)` →
  `if (false)` for the service rows; dropping `|| !FULL_BUILD` for the
  industrial button) reds each **by name**:
  `FAIL  transit checkbox row hidden on this build  shown=true full=false`.
- **This clears V4's standing blocker.** *"Fix the gating before scheduling
  anything"* no longer applies — the estate is honest against both builds.
  **What** to schedule changes CI behaviour and stays a proposal.

### Method notes that generalise

- ⚠️ **Reproduce, then falsify the FIX too.** Every fix here was mutated to
  confirm it reds by name. The V1 mutation harness (patch → pytest → record
  which names red → revert) found the fix's own weak points in ~90 s.
- ⚠️ **Shell → `node -e` escaping cost two failed patch attempts.** Write the
  patcher to a **file** in the scratchpad and run it. Anchor on unique
  multi-line strings and **assert the match count is exactly 1** before writing.
- ⚠️ **A patcher that writes per-file inside a loop leaves partial state when a
  later file fails.** Happened twice (amenity written, bike failed). Either
  validate every file first, or `git checkout` the written ones before retrying.
- **`git fetch` before `git merge-base --is-ancestor`.** See §2.

### Environment quirks hit this session

- **The both-builds sweep of 10 scripts × 2 builds took ~35 min** serially and
  must be **backgrounded** (`run_in_background: true`) — the Bash tool caps at
  600 s. `verify-peek.js` legitimately needs **>219 s**; the sweep used a 300 s
  `timeout`.
- ⚠️ **Do not edit `tools/profiling/verify-*.js` while a sweep is running** —
  each invocation reads the file fresh, so mid-sweep edits change what is being
  tested. README/doc edits are safe.
- Foreground `sleep` is blocked by the harness; use `until <cond>; do sleep N; done`.
