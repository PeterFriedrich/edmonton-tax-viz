## 3. Technical Learnings

- ⚠️ **THE ONE TO KEEP: "narrative, not a computation others cite" was the wrong
  triage, and it cost a live false claim.** S100 ranked
  `FINDINGS_revenue_scale.md` §4-5 **last** of seven next-steps on exactly that
  reasoning. It was **quoted by a user-facing string**, via a code comment
  naming it as the authority. **Nothing had checked whether prose was cited by
  code.** Grep for a doc's *name* in `web/`, not just for its claims.
- ⚠️ **A "where is this surfaced in the UI?" grep is worth running even when you
  are confident of the answer.** The task assumed the $125.4M figure was in the
  UI. It is **nowhere** — docs only. The same grep is what surfaced the false
  string. The premise check and the find were the same command.
- ⚠️ **LLM-supplied worked examples were plausible-looking construction, not
  lookups** — well-formed Edmonton addresses, believable magnitudes, and
  round-ish values (`410740000`, `404700000`) that match **nothing** in a
  439,685-row dataset. Two of three had a real property behind them with the
  wrong number attached, which is the harder failure to spot than a fabricated
  address.
- ⚠️ **`q7d6-ambg` has NO zoning field.** Live schema: `account_number,
  house_number, street_name, neighbourhood_id, neighbourhood, ward,
  assessed_value, tax_class, garage, mill_class_1, tax_class_pct_1, latitude,
  longitude, point_location`. Zoning is `dkk9-cj3x`. **Any claim pairing an
  assessed value with a zone code already spans two datasets.** Note the API's
  `mill_class_1` is the CSV's `Assessment Class 1`.
- ⚠️ **`assessed_value` is a STRING in the Socrata API** — `assessed_value=410740000`
  returns HTTP 400; quote it.
- ⚠️ **Calgary does NOT publish exemption status as open data.** Verified
  against the live schema of `4bsw-nn7w` — 22 fields, no exempt/taxable flag.
  It is on their **assessment notice** only. A brief asserted the stronger
  version; sending it would have been checkable and wrong.
- ⚠️ **Any GIPOT figure from 2020–2024 is a 50% payment** (75% in 2019, 75% in
  2025, 100% from 2026), so it reads ~2× low as a tax equivalent. And the City
  of Edmonton **publishes no GIPOT dollar amount at all**.
- **Closed rings must not be clipped.** `REGIONS` are deliberately unclipped:
  clipping a municipality replaces its far side with a straight run along the
  clip box that **draws as a real border**. The river/highways are clipped
  because they are *open* shapes. Parkland (66.7% inside) runs off the edge.
- **Two upstream sublayer traps, now pinned by tests:** Strathcona County is a
  **Specialized Municipality (104)**, not 114 with the other counties; and
  **"Leduc" is two different polygons** — the city (78) sits inside the county
  (114), and querying the wrong one returns a plausible shape of the wrong
  scale with **no error**.
- **`TODO.md` lagged reality twice more this session** — the Tier-3 boundaries
  item claimed unbuilt work that shipped 2026-07-27, and the item above
  contradicted the item below it. The memory note on this exists and it still
  keeps happening.
