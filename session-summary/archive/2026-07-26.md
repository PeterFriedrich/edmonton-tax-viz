### ✅ 1. P2.2 — pipeline liveness, guarded on BOTH sides (PR #96, `6d7ce5c`)
The stated risk was "GitHub auto-disables cron workflows after 60 idle days →
the site silently serves stale data". **Built as prevention AND detection,
because prevention alone has its own silent failure.**

- **Prevention:** `refresh.yml` checks out with
  `${{ secrets.HEARTBEAT_TOKEN || github.token }}`. A PAT push counts as repo
  activity where a `GITHUB_TOKEN` push may not. **Falls back cleanly** when the
  secret is absent — forks and a revoked token still work.
  - Verified the one real hazard: a PAT push *does* trigger workflows (unlike
    `GITHUB_TOKEN`), but the commit step stages `web/data` only and
    `deploy.yml:28` excludes `web/data/**` → **no deploy loop**. Commented
    inline so it stays true.
- **Detection:** the frontend ages `status.json`'s `last_checked` and raises the
  existing `#banner` past **`STALE_DAYS = 14`** (two missed weekly runs, Peter's
  call). Covers EVERY cause of stoppage — including the PAT expiring — needs no
  secret and nothing to renew. **The principle: the thing that detects the
  outage must not be the thing that can go out.** Hence the browser.
  - Backend banner (year-hold) always wins. Every uncertain input stays silent:
    missing / unparseable / **future** `last_checked` (visitor clock skew), or
    an unreachable manifest.
  - Uses `last_checked` (bumps every run), **not** `generated` (bumps only when
    data content changes) — it answers "did a run happen", the actual question.
- **Third thing, found while building:** the commit step's
  `git push || echo "Nothing to push."` swallowed **auth** failures, not just
  no-ops. An expired token would have failed the push, reported the run GREEN,
  and taken the heartbeat down silently — the exact failure being fixed.
  Replaced with an explicit `git diff --cached --quiet` test; all four branches
  exercised in a scratch repo (no-op / heartbeat bump / same-day re-run /
  non-data file changed).
