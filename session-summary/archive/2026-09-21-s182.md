## 3. Technical Learnings

- ⚠️ **AN MTIME IS NOT EVIDENCE OF EXECUTION, AND A COSMETIC RE-RENDER LOOKS
  EXACTLY LIKE A RE-VERIFICATION.** Every file in `web/notebooks/` read as one
  day old; four of five had not fetched a live source in **23 days**. The only
  honest signal was the *"re-executed against live data"* line printed on each
  page's own face. **Peter's framing — "or is it just 'updated on so and so'" —
  named the defect before it was measured.** Same family as
  `guards-must-measure-data-not-metadata`, and as `archived-tables-still-answer`.
- ⚠️ **A WELL-BUILT DETECTOR WITH NO TRIGGER IS NOT A DETECTOR.** The evidence
  notebooks' invariants were correctly written to fail when a publisher fixes
  the defect — and nothing ever ran them, so the mechanism had never once been
  exercised against a fix. **This is the third instance of this exact shape in
  the project's history** (`_classify` warning → unread log for ~70 days; the
  four automated reports → GitHub issues nobody pushes to a model; this).
- ⚠️ **AN APPEND-ONLY INDEX CAN CONTRADICT ITSELF, AND THE NEWER ROW LOSES.**
  `DECISIONS.md:365` (2026-09-14) asserted the temporal lens was full-only, six
  weeks after `:200` (2026-07-31) recorded its promotion. **A locked-decision
  log protects the decision, not the parenthetical facts asserted around it** —
  and those are read with the same authority.
- ⚠️ **EXIT 0 IS THE ABSENCE OF EVIDENCE, NOT EVIDENCE.** The recheck requires
  a notebook to *show* its invariants fired. That single rule caught both roads
  notebooks on the first live run. The converse rule — S181's — is that a
  descriptive script exiting 0 must never be reported as "PASS".
- **"COULD NOT CHECK" AND "SOMETHING MOVED" ARE DIFFERENT FINDINGS AND THE
  FIRST IS LOUDER.** Both exit non-zero; only one is a measurement.
- **A JUSTIFICATION NOTEBOOK'S BEST SECTION IS THE SOURCE CONTRADICTING
  ITSELF.** The City calling one inventory *"linear km"* on p4 and defining
  distances as *"lane km"* on p16 — fetched live from the primary PDF — settles
  more than any argument, because it shows the unit is **unsettleable from
  wording** and forces the magnitude argument.
- **VERIFY THE HANDOFF'S CLAIMS, NOT JUST ITS TASKS.** S181 said the refresh
  was overdue; it was not (see ❌2). Two sessions had carried that forward
  unchecked. Same lesson as `todo-can-lag-executed-work`, applied to a handoff.
