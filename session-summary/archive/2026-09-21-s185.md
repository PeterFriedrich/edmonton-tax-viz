**(c) THE LIGHT PALETTE IS HELD — Peter's call, with reasons.** Designing the
light values surfaced that a chrome-only light mode is **the wrong build** here:
1. **Redesign, not a flip.** The chrome sits on the map, which stays dark this
   phase. Bare-text elements (`#title`, `#legend`, `#millrates`) have **no
   background** — light text on the dark map — so dark ink makes them
   **invisible**; the translucent-dark pods (`rgba(12,12,20,·)`) would have to
   become opaque light islands. New chrome, not a token swap.
2. **The glare paradox.** People enable OS light preference to **reduce** glare;
   a dark map is already low-glare, so light chrome only makes the app
   **brighter** — against the point. The light mode that serves a
   light-preference user is a **light MAP** (ramp + backdrop rework), the
   daylight/print/projected viewing case.
   Recorded in `docs/UI.md` → Planned → Light mode (the note already anticipated
   the map-ramp problem) and DECISIONS 2026-09-21.

## 3. Technical Learnings

- ⚠️ **SVG presentation attributes do NOT resolve `var()`.** `fill="var(--x)"` is
  inert; `style="fill:var(--x)"` (CSS in the style attribute) works, and so does a
  stylesheet rule. Confirmed by computed-style read. This is why the index.html
  marks moved to `style=`.
- **The tokenization boundary is chrome vs DATA, not styles.css vs index.html.**
  The legend gradient and set-aside swatch live in `styles.css` but are the map's
  ramp reproduced — left literal. The sparkline marks live in `index.html` but are
  chrome-on-a-panel — tokenized. Sort by what the colour *means*.
- **A light theme can't be decoupled from the map by tokens alone.** The tokens
  decouple cleanly, but the *visual* result can't: bare-text-on-map elements and
  translucent pods both assume a dark backdrop. "Dark map + light chrome" is a
  real redesign. This is the load-bearing finding.
- ⚠️ **`pkill -f "<pattern>"` shot its own shell again** (exit 144) — the pattern
  `resolved ==` matched the heredoc running the check. The
  `pgrep-watchers-match-themselves` memory, hit live. Don't `pkill -f` a string
  that appears in the command doing the killing.
- **A `re.sub` with `(?:.*\n)*?` backtracks catastrophically** on a big file —
  one verification hung 120s and was killed. Used string `.index()` slicing
  instead.
- **Important locations:**
  - `web/styles.css` — the `:root` token block (top of file, after the leading
    comment) + `--mark`/`--mark-2`/`--band` near `--accent`.
  - `web/index.html` — sparkline/chart/needle marks now `style="fill:var(--mark)"`
    etc. (was lines ~581, 4970–5018, 5121–5159, 5386 pre-edit; **don't cite line
    numbers, they drift — use CODEMAP**).
  - `docs/UI.md` → Planned → **Light mode** (resume path).
  - `/home/opc/research/edmonton-tax-viz/light_mode_theme_{research_prompt,rounds}.md`.
