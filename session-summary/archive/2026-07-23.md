## 3. Technical Learnings
- **The whole pass = "view vs render-mode" applied repeatedly.** Glass and Infill
  both turned out to be modes of another view wearing a top-level-view costume.
  Glass folded cleanly (matches Money mechanically AND on build-tag); Infill
  folded but crosses a tag boundary (Dev public / Infill full) → the fold is only
  realizable *because* the `BUILD` flag gates per-control, not per-view.
- **The two-build tag surface and the regroup ARE one decision** (as S62 warned):
  every fold either inherited a tag (Glass=public like Money) or set one
  (Infill/Industrial = full-only). Deciding grouping settled the tags for free.
- **Decision #7 was mobile-driven but solved structurally, not with CSS** — the
  right response to "the spike checkbox is bad on phone" was to flatten the
  nesting (checkbox+sub-picker → one 3-way selector) so BOTH platforms inherit a
  clean control. This is the "structure-before-mobile" sequencing in action.
- **Industrial (#8) had to be full-only to keep #7 clean** — it's the only
  choropleth-only Dev metric, so leaving it public would reintroduce dead options
  in the brand-new Detail selector. The two decisions interlock.
- **Recording pattern that worked:** per-decision, edit BOTH `DECISIONS.md`
  (append to the new "Controls & lens grouping" section) AND `CONTROLS_MATRIX.md`
  §7 (a running table), then one focused `docs: lock regroup decision #N — …`
  commit + push. Small pushed commits, Oracle-box proactive-push rule.
- **Key file locations:** `docs/CONTROLS_MATRIX.md` §7 (the 8 decisions) + §2
  (finalized tags); `docs/DECISIONS.md` "## Controls & lens grouping" section;
  `TODO.md` "BUILD ONCE" item; `docs/PLAN_public_release.md` §2a. Gating
