## 3. Technical Learnings

- **Panel-ness is a property of the VIEW; having history is a property of the
  DATA. Never conflate them.** `hoodPanelLens()` vs `temporalFor()`. The
  one-line version was elegant and wrong, and its blast radius was seven
  consumers wide — including two nobody would list from memory: the panel-mode
  **tooltip reduction** (it is a *trade* — detail for a panel that carries it —
  so where no panel opens it is a deletion) and the peek card's **own tap**
  (which otherwise commits into an empty panel and strands the phone with
  neither surface).
- ⚠️ **Writing the regression test found a SECOND hole in the fix that
  reasoning had missed.** The deliberate opt-in (`panelByChoice`, bought by
  pressing `#hoodmode-btn`) routes a tap *past* the card branch straight to
  pinning — so a fix verified from a fresh load still left the tap dead once the
  user had opted in. **A touch check that only ever runs from a clean state is
  not covering touch.**
- **`applyView` is `async`** (it awaits lazy data fetches before
  `syncPinnedPanel`). A `page.evaluate` that calls it without `await` reads the
  state *before* the sync and reports a bug that is not there — this cost one
  false alarm before it was caught.
- **The verify suite's blind spot is combinatorial, not per-file.** Each script
  owns a surface (`verify-peek`) or a view (`verify-services`); nothing owned
  *surface × view*. `CONTROLS_MATRIX.md` is the doc that makes that state space
  visible, which is why it got the substantive update rather than `UI.md`.
- **`$CLAUDE_EFFORT` is a real env var** (`high` this session). The **model** has
  no on-disk record — it can only come from the session's own context, and a
  mid-session `/model` switch may not be reflected there. Both facts are now
  encoded in the `/handoff` skill's new §0.
- **On `PROJECT_AUDIT.md`'s idempotency claim (self-correction):** the grep
  behind it (`datetime.now()`) would **not** have caught `dt.date.today()`,
  which is what `generate_status.py` actually uses. Re-checked properly: `src/`
  and `main.py` are genuinely clean and the conclusion stands, but the evidence
  was thinner than the doc implies.
- **Falsification, done properly, is cheap and worth it.** The new
  `verify-peek.js` block fails against the broken build with **exactly 4
  failures, all of them the new checks, zero collateral**. ⚠️ An earlier
  falsification run showed **10** failures — six were SwiftShader picking flake
  from running two Chromium instances concurrently, which the script's own
  header warns about. **Run verify scripts serially when the result is
  evidence.**
