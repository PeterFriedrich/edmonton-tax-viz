## 3. Technical Learnings

- **Panel-ness is a property of the VIEW; having history is a property of the
  DATA. Never conflate them.** `hoodPanelLens()` vs `temporalFor()`. The
  one-line version was elegant and wrong, and its blast radius was seven
  consumers wide — including two nobody would list from memory: the panel-mode
  **tooltip reduction** (it is a *trade* — detail for a panel that carries it —
  so where no panel opens it is a deletion) and the peek card's **own tap**
  (which otherwise commits into an empty panel and strands the phone with
  neither surface).
- ⚠️ **Writing the regression test found a SECOND hole in the fix that
  reasoning had missed.** The deliberate opt-in (`panelByChoice`, bought by
  pressing `#hoodmode-btn`) routes a tap *past* the card branch straight to
  pinning — so a fix verified from a fresh load still left the tap dead once the
  user had opted in. **A touch check that only ever runs from a clean state is
  not covering touch.**
- **`applyView` is `async`** (it awaits lazy data fetches before
  `syncPinnedPanel`). A `page.evaluate` that calls it without `await` reads the
  state *before* the sync and reports a bug that is not there — this cost one
  false alarm before it was caught.
- **The verify suite's blind spot is combinatorial, not per-file.** Each script
  owns a surface (`verify-peek`) or a view (`verify-services`); nothing owned
  *surface × view*. `CONTROLS_MATRIX.md` is the doc that makes that state space
  visible, which is why it got the substantive update rather than `UI.md`.
- **`$CLAUDE_EFFORT` is a real env var** (`high` this session). The **model** has
  no on-disk record — it can only come from the session's own context, and a
  mid-session `/model` switch may not be reflected there. Both facts are now
  encoded in the `/handoff` skill's new §0.
- **On `PROJECT_AUDIT.md`'s idempotency claim (self-correction):** the grep
  behind it (`datetime.now()`) would **not** have caught `dt.date.today()`,
  which is what `generate_status.py` actually uses. Re-checked properly: `src/`
  and `main.py` are genuinely clean and the conclusion stands, but the evidence
  was thinner than the doc implies.
- **Falsification, done properly, is cheap and worth it.** The new
  `verify-peek.js` block fails against the broken build with **exactly 4
  failures, all of them the new checks, zero collateral**. ⚠️ An earlier
  falsification run showed **10** failures — six were SwiftShader picking flake
  from running two Chromium instances concurrently, which the script's own
  header warns about. **Run verify scripts serially when the result is
  evidence.**

## 3. Technical Learnings

- ⚠️ **The 2026 mill rates were published 2026-04-29 and nobody noticed until
  2026-08-06 — a four-month blind spot, and the root cause of this whole
  session.** `RUNBOOK.md` §1 step 1 assumed rates arrive *after* the roll ("the
  hold can last months by design"). For 2026 that **inverted**. The assumption
  is now flagged in the RUNBOOK and the 2027 January roll should be a same-day
  clear rather than a months-long banner.
- **"Why is there no pipeline for the mill rates" has a real answer, and it is
  not laziness: auto-fetching is the BUG, not the missing feature.** Rates are
  year-keyed and must match the assessment roll, so "fetch the latest" would
  silently bill an old roll at new rates. Now locked in `DECISIONS.md`
  (2026-08-06) so it does not get re-litigated.
  - The secondary reason, **measured not assumed**: the source's vocabulary
    broke **4× in 12 years** — `Non-Residential`→`Non Residential` (2019, the
    join key), `Municipal Tax Rate`→`Municipal` (2019), `Transitional
    Residential` added (2018), and **`Farmland` DELETED (2025)**. That last one
    is exactly the case that needs a human's flagged assumption rather than a
    fetcher's guess. It also changes **once a year**, so weekly polling buys
    nothing.
- ⚠️ **`tools/todo_archive.py` was silently burying live work, and had been for
  6 days.** A closed *parent* can carry unchecked *children*; archiving it moved
  them into a file whose own header reads *"Nothing here is a to-do"*, so nobody
  would ever look. The upstream Edmonton Open Data bug report went in on
  2026-07-31 riding the closed temporal-graph item. **This is the third bug of
  the same family in that one script** (the archive-overwrite bug, the
  accumulating-banner bug, now this) — all cases where *the second and later
  runs are a different program from the first*. Guard added; if a fourth shows
  up, suspect the same shape.
- **The digest found a bug in itself on its first run.** It flagged 2014–2024 as
  "missing from `mill_rates.json`" — but the file deliberately carries no
  history. Only years **≥ the pin** matter. Caught because the thing was run
  rather than reasoned about.
- ⚠️ **One digest check is genuinely NEW coverage, not a reminder.**
  `generate_status.py`'s `DATA_YEAR` / `RATE_YEAR` are *separate constants* from
  `main.py`'s `ASSESSMENT_YEAR`; `RUNBOOK.md` §1 step 6 warns that forgetting
  them silently misreports the site's own vintage, and **nothing enforced it**
  until now.
- **Falsification before tests, again, and again it paid.** All 8 ACTION paths
  were driven red by hand (monkeypatching `main`'s pins and pointing the module
  constants at temp fixtures) *before* `tests/test_vintage_report.py` was
  written. A digest that cannot go red is worse than no digest — it reads as
  reassurance.
- **Delivery design: a GitHub issue, not SMTP.** It gives email via GitHub's own
  notifications with **no second credential** (`HEARTBEAT_TOKEN` stays the only
  secret, which `PROJECT_AUDIT.md` treats as a property worth keeping), and the
  issue is itself a checklist with state. **An issue is filed every month even
  when all-green, on purpose:** a digest that only speaks up when something is
  wrong is indistinguishable from one that has silently stopped running.
- **Network failures report `UNKNOWN`, never `ACTION`** — the rule inherited
  from `check_year_alignment.py`: a guard must not manufacture an alarm out of
  an unreachable source.
- **S96's handoff was stale on arrival.** Its "#1 next step: push the branch and
  open the PR" was already done — PR #172 merged at 04:34Z. Consistent with the
  standing `todo-can-lag-executed-work` lesson: **check state before acting on a
  written next-step**, including one written hours ago.
