## 4. Technical Learnings (don't re-derive)

- **Coordinate rounding AFTER a validity pass re-breaks geometry.** The first
  zoning export rendered two stray filled black triangles: rounding to 5 dp
  at write time re-introduced degenerate rings → deck.gl's tessellator
  artifacts. Fix in `export_zoning_web`: `shapely.set_precision(g, 1e-5)`
  (topology-aware grid snap) after `buffer(0)`, BEFORE writing — the file
  then holds exactly the validated geometry. Debug path that worked:
  screenshot → `map.unproject` the artifact pixels → probe raw + exported
  files at those lon/lats (raw was fine; exported `res` MultiPolygon was
  invalid).
- **Frontend strokes can't draw hood boundaries here** — the served hood
  polygons are already setback-shrunk 45 m, so outlining them gives doubled
  lines. Bake gaps into the geometry instead (clip to the setback union).
- **The DC bucket hides the big-box power centres**: the 8 dc-dominant hoods
  are South Edmonton Common, Terra Losa, Mill Woods Town Centre, Calgary
  Trail South, Summerlea, Place LaRue, McCauley, Strathcona Junction.
  Recorded in ANALYSIS_BACKLOG 1; motivates item 3 (DC provision scrape —
  each DC polygon's `url` points at its per-site bylaw provision page,
  ~1,070 sites).
- **No hood is mixed-dominant** (true mixed zones ≈ 317 acres citywide) — any
  mixed-use analysis must test `frac_mixed > 0`, not dominance.
- **Zone names mislead; purpose statements decide.** Documented in DATA.md §5.
- **Palette method**: candidates per semantic hue → brute-force through
  `dataviz` skill's `validate_palette.js` (`--mode dark --surface "#0a0a0f"
  --pairs all`) → best min-adjacent ΔE wins. 7 chromatic all-pairs ≥12 is
  infeasible; 10.6 + secondary encoding is the documented landing.

  `tools/profiling/` need `NODE_PATH=tools/profiling/node_modules`.

## 4. Technical Learnings (don't re-derive — these cost real time)

- **deck.gl `CollisionFilterExtension` renders NOTHING under this interleaved
  MapLibre overlay** (deck 9.0.38, `MapboxOverlay({interleaved: true})`): the
  TextLayer mounts, `collisionEnabled` true, and every label is culled — the
  collision pre-pass draws nothing. Confirmed by stripping the extension at
  runtime (all 406 labels appear). A non-interleaved overlay fixes it BUT
  showed a canvas-compositing glitch over the legend in the probe and would
  change the rendering mode under all four shipped views — rejected. The JS
  greedy cull replaces it; don't retry the extension without checking this.
- **deck TextLayer draws glyphs LARGER than `getSize`**: the characters
  sublayer gets `sizeScale = atlas glyph height / fontSize` = **1.325** here
  (SDF padding + font line metrics; read it via
  `layerManager.layers.find(l => l.id.includes('characters')).props.sizeScale`).
  Cull boxes must scale by it (`LABEL_DRAW_SCALE = 1.35`) or long names
  render past their box — the visible tell was "STRATHCONA JUNCTION|RITCHIE"
  butted together while the overlap test swore 0 overlaps.
- **Flat chars-per-em width estimates drift with glyph mix** (RITCHIE vs
  WHITEMUD); measure each name once with canvas `measureText` using the SAME
  font string as the layer (`LABEL_FONT_FAMILY`/`LABEL_FONT_WEIGHT` consts
  shared by both) — atlas advance agrees with canvas measure.
- **Culling projections were NOT the problem**: deck's cached viewport and a
  fresh `WebMercatorViewport` from the map camera project identically after
  `jumpTo` + settle (probed at zoom 12.2; stale-viewport hypothesis dead).
- `overlay._deck.props.layers` is the deterministic place to assert the layer
  stack; `layerManager.layers` holds finalizing layers for a beat after
  `setProps` (and includes sublayers).
- Names are ALL-CAPS in the data (kept — standard cartographic area-label
  style); one non-ASCII: WÎHKWÊNTÔWIN. Longest: EDMONTON RESEARCH AND
  DEVELOPMENT PARK.
- Both TextLayer and CollisionFilterExtension ARE in the already-loaded
  `deck.gl@9.0.38/dist.min.js` bundle — no new script tags needed.
