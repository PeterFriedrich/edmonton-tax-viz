## 4. Technical Learnings (don't re-derive)

- **The ratio's high tail is entirely non-residential land.** Residential kept
  subset (n=223): p2.5 ≈ **$258**, p97.5 ≈ **$916**, max $2,197 — vs full kept
  set (n=339): $264 / $3,253 / $18,025. Floor barely moves, ceiling drops
  ~3.5×. Same §6.2 mill-rate mechanism, seen through the road denominator.
  This made the anchor-rescale decision (the open design question from
  Session 7) unambiguous: without it, residential hoods crush into the ramp's
  bottom. Recorded in FINDINGS §6.4.
- **At the default 5% ghost opacity the lens fade is near-invisible**
  (fade α90 × 5% layer opacity ≈ nothing) — the lens reads as "colour
  disappears from non-res hoods" until the slider is raised. Known + accepted
  (noted in UI.md); a tunable if Peter ever wants the fade to read at 5%.
- **Verification pattern that worked well:** compute the expected quantiles
  independently in Python from the served GeoJSON, then read the live legend
  DOM headlessly and diff. `verify-lens.js` also reaches layer accessors via
  `overlay._deck.layerManager.layers` and calls `getFillColor` directly —
  no pixel-reading needed for colour assertions.
- Top-level `const`/`function` in the page's classic script are reachable
  from `page.evaluate` (global lexical bindings) — `state`, `ratioKept`,
  `setPrismOpacity`, `buildLayers` all callable from Playwright.
- Swiftshader screenshot rule still holds (~60 s wait with roads layer);
  `shot-ratio-lens.js` is the committed multi-click + evaluate example.
- **Deploy trigger reminder:** merging to master does NOT deploy — the
  "Refresh map data" workflow is dispatch/cron only; `gh workflow run
  "Refresh map data"` after merge. It pushes an `Auto-refresh map data`
  commit, so `git pull --rebase` before pushing anything post-deploy.
