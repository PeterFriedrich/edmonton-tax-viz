## 3. Technical Learnings

### ⚠️ The through-line: three measurements aimed only where they expected the answer

This is the session's one real finding, and it repeated in three unrelated
places within hours.

1. **S140's harness count was wrong by 15×, and it killed Condition 2.** The
   audit said *"39 of 65 scripts reach page globals; an eight-name `window.__app`
   shim covers them all"*. That came from `grep -lE` **for a pre-chosen list of
   eight names** — a method that can only confirm the list it is given.
   Re-measured the other way round (take all **377** top-level declarations, then
   find which appear as **free variables** — not locally declared, not parameters
   — inside `.evaluate`/`.waitForFunction`/`$eval` bodies): **122 distinct page
   globals across 48 of the 65 scripts.** `state` 172 bodies, `overlay` 93,
   `tooltipFor` 33, `map` 29, `applyMetric` 27, `rampColorAt` 18. **`noHover`,
   one of the chosen eight, appears in none.** A shim that size re-exports a
   third of the file, so module scope isolates nothing → **the flip was withdrawn
   and `"use strict";` shipped instead.**
2. **Two verify scripts pinned live data.** `verify-glass-cell.js` /
   `verify-grid-loading.js` asserted cell counts `34671`/`93201`; the 2026-09-02
   auto-refresh legitimately moved them to `34662`/`93180`. Now derived from the
   served files — the rule `verify-smoke.js`'s own header already states.
3. **The one guard aimed correctly found a real bug — and nobody read it.**
   `verify-reference-layer.js` had been correctly reporting `#budget` /
   `#budget-pod` missing from `CHROME_IDS` (so place labels could draw over the
   budget panel in the full build) **since 2026-09-02**. The page was fixed, not
   the test.

⚠️ **Corollary, now an open `TODO.md` item: the 65 scripts gate nothing.**
`refresh.yml` runs `verify-smoke.js` only; `tests.yml` runs none. That is how
four scripts stayed red for three days.

### Verified facts worth not re-deriving

- **`Content-Length` is not a progress denominator here.** GitHub Pages gzips
  `value_grid_50.json`: `Content-Length` **2,915,229** vs decompressed body
  **8,002,725** — a naive `received/Content-Length` bar finishes at **~275%**.
  Verified with `urllib` + `certifi` against the live site. A real percentage
  needs the DECOMPRESSED size served in the manifest (data-contract change).
- **A `HEAD` whose response body is never touched is torn down as
  `net::ERR_ABORTED`.** The size still arrives correctly, so nothing looks
  broken — it only surfaced as `verify-smoke.js`'s *"no failed requests"* going
  red. `await r.arrayBuffer()` on the empty body retires it. Three variants were
  measured side by side in one page: headers-only **failed**, consumed-body
  **clean**, Range-GET clean (but python `http.server` ignores `Range`).
- **`HEAD` + `Content-Length` is a free, self-updating size source** — 1.07 MB /
  2.78 MB on Pages, and honestly 7.6 MB against the local server, which does not
  gzip. Both are what that server actually sends.
- **The extracted script parses clean as ESM** (`node --check` on the `<script>`
  body saved as `.mjs`). This is now the ONLY thing that would catch a duplicate
  top-level declaration, since the module flip was withdrawn — it is the sharpened
  purpose of the still-unscheduled CI checker.
- **Top centre is NOT free chrome space.** `#views` reaches into it on a wide
  screen; the first `#gridbusy` sat straight through it at 1280. Bottom centre is
  clear on desktop; on a phone the bottom strip is full AND the top is under the
  open options panel, so the free band is between them.
- `tools/codemap.py` `BANNER` matches at **any** indent, but `SYMBOL` only at
  indent ≤ 4. That is why banners inside `boot()` work while nothing inside it
  gets a row.

### Environment quirks hit this session

- ⚠️ **`ps aux | grep -c "[c]hrome"` is not enough before trusting a red.**
  `verify-peek.js` failed twice — once in the sweep, once in a "run it alone"
  that still had the sweep's Chromium winding down — and **passes clean on a
  genuinely quiet box**. I called it a flake before checking, then believed the
  second red. Both were wrong. Wait for the sweep process to actually exit.
- ⚠️ **A `cd` in a Bash call persists** (hit again: `cd web/data` broke the next
  call's relative paths). Use absolute paths. Same quirk S140 recorded.
- ⚠️ **`pgrep -f "verify-…"` waiters match their own command line** and never
  exit. Wait on the sweep's **PID** instead. Four such orphans from earlier
  sessions are still running on this box, aged **11, 35, 35 and 51 days** —
  Peter was told, has not asked for a cleanup.
- ⚠️ **`cmd_a && cmd_b <<'EOF' … EOF` followed by `echo "done"` prints "done"
  even when `cmd_a` failed** and `cmd_b` never ran. This produced a false
  "decision logged" — `DECISIONS.md` was untouched. Caught by grepping the file.
  **Verify a write landed; do not trust a trailing echo.**
- The 42-script sweep takes **~35–40 min** serially on this box (software
  SwiftShader, no GPU). Ran it **four times** this session.
- `verify-deviation.js` writes `deviation.png` into the CWD (repo root when run
  per the docs). Now in `.gitignore` beside the two `shot-mobile.js` ones.
