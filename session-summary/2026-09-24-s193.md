## 3. Technical Learnings
- ⚠️ **Only `verify-smoke.js` (and now `verify-blurbs.js`) run in CI.** The other ~45 verify scripts run only when someone runs them. This session found **four** local checks already red on master: verify-change's title check, glass-no-slider's Ratio default, and the two build-gate reds above. That's the "channel nobody reads" failure mode, and it's why the blurb guard went into `deploy.yml`.
- **Test the blurb functions, not the render, then tie them back with a DOM oracle.** Clicking through states under swiftshader cost seconds per state (the grid sweep took 6 minutes). Calling `currentBlurb()` after setting state takes 30 ms for 150 states. The wiring half (`DOM === plain(currentBlurb())` after each click) is what keeps that from being a test that agrees with itself.
- **Top-level `let` bindings (`camFlat`, `gridData`, `gridCell`) are assignable from `page.evaluate`.** `verify-blurbs` relies on this, and restores them afterwards.
- **The landing blurb is static HTML.** Nothing calls `setBlurb` on load (`syncMode()` at init only re-renders on a camera change). If `METRICS.revenue_per_acre.blurb` or `moneyBlurb()` changes, update the `<div id="title-p">` markup too, or `verify-blurbs` fails "landing".
- **`withColourClause` matches `colour is square-root[^.]*\.` case-sensitively.** Keep that clause mid-sentence and lowercase in the money/glass P2.
- **`scripts/check_cost_copy.py`** only reads `blurb:` literals and visible HTML text, **not `blurbNote:`**. Any quoted rate must stay in P1/P2 (`blurb:`) or in Data & Methods. $5,970, $3,350, "2017 roads-maintenance budget", $600,000 and $1,900,000 live only in the Services blurbs.
- **`verify-transport-cost.js`** requires the roadscost text to contain "Operating only" and "lifecycle". It now reads `blurb + blurbNote`.
- **Honesty lines other scripts guard:**
  - `verify-res-revenue` / `verify-nonres-revenue` require *"subset of Revenue"* and *"not all of what the land pays"* (in `blurbNote`);
  - `verify-ratio-denom` requires fire's *"Demand, not response coverage"*.
- **System `python3` on this box is 3.6.** `scripts/build_site.py` needs the venv: `.venv/bin/python scripts/build_site.py --src web --out <dir>`.
- **The shell kills itself** (`pkill -f`/`pgrep -f` patterns match their own shell, exit 144; per memory). Kill servers by PID. One backgrounded `http.server` failed to bind because an earlier one was still on the port. It was confirmed to be serving the same `web/`.
- **`check(name, cond)` in `verify-development.js` ignores a third argument.** Diagnostic extras there are silently dropped.
