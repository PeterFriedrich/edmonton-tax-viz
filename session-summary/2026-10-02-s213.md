## 3. Technical Learnings
- **Filtering check runs by `url-state` prefix mis-counts.** The change-filter
  job is named `url-state-changes`, so a docs PR looks walked. Classify a PR as
  walked when a `url-state*` check ran for more than 60 s. PRs before #637 had
  a single `url-state` job and no shards.
- **The `url-state` CI logs carry `walking:` and `(N round trips)` per shard.**
  To compare sharded against unsharded, `gh run view <id> --log` and parse the
  `ok  `/`FAIL` names.
- **Playwright 1.61.1:** a default `launchServer()` spawns
  `~/.cache/ms-playwright/chromium_headless_shell-1228/chrome-linux/headless_shell`.
- **`verify-about` link checks:**
  - a 429 is a designed SKIP, so the check count varies 78/79 with GitHub
    rate limits;
  - a 5xx or a timeout is a FAIL, so a down host reads as a broken link.
- **`verify.js` always injects the preload.** For a no-preload run, call the
  script directly and count `^PASS`/`^FAIL` yourself. The A/B script pattern
  is in §7 of the findings.
- **`check_served_columns.py` already covers data-gated controls on the
  refresh path.** `url-state` never runs on refresh pushes, so don't re-raise
  that as a gap.
- ⚠️ `git stash -u` before a branch switch swallows uncommitted docs. Commit
  WIP instead.
