## 3. Technical Learnings
- **A migration can write fake outcomes.** Status fields stamped in bulk on a system-cutover day look like decisions. The tell was a `status_date` spike (127 rows on 2 days) coinciding exactly with the creation-date spike on the other system. I first read the pairs as "the City reconsidering its refusals" and published that. The correction came only when Peter's follow-up question forced a per-year breakdown of refusal dates. **Check the status_date distribution before trusting any outcome column.**
- A fact-check of my own prose caught a false claim: "2016 inflated by hackathon rows". Only 11 of 111 were hackathon rows. I measured it and rewrote the line.
- The recheck workflow (`scripts/recheck_evidence_notebooks.py`) runs an **explicit list** (`EVIDENCE`, `JUSTIFICATION`), not a glob. A notebook placed in `notebooks/exploration/` is NOT rechecked. That is deliberate here: it is a landscape report whose invariants guard its own readings, not a publisher defect.
- `tools/inject_notebook_mobile_css.py` globs every `web/notebooks/*.html`, so any rendered page gets the fix automatically. `tests/test_notebook_mobile_css.py` enforces it.
- Render command: `.venv/bin/jupyter nbconvert --to html notebooks/exploration/04_dataset_requests.ipynb --output-dir web/notebooks --output dataset-requests`, then `.venv/bin/python tools/inject_notebook_mobile_css.py`.
- Socrata catalogue API for the domain: `https://api.us.socrata.com/api/catalog/v1?domains=data.edmonton.ca&limit=1000&offset=N`, about 2,088 assets.
- **The `web/notebooks/` footer still says every source is under `notebooks/standalone/`.** That is no longer true for this one; its meta line says `notebooks/exploration/`. It is cosmetic and was left alone.
- A chained `cd dir && .venv=... &&` shell line failed silently mid-chain, and an edit didn't apply until I grepped for it. Verify edits landed when chaining.
