## 3. Technical Learnings

- ⚠️ **The repo already knew what the brief missed — and the S140 findings doc
  over-claimed it as novel (caught in phase 3, and corrected in §7).**
  `docs/TOKEN_EFFICIENCY.md` "Files to watch" has carried the qualitative claim
  for weeks: *"every verify script calls bare globals inside `page.evaluate`;
  module scope is not global scope, so a split would break the whole test
  harness."* The brief's §3 never picked it up. **This session's actual
  contribution is the count (39/65, 337 sites), the eight-symbol shim that
  fixes it, and that it is not a blocker.** Same shape as S139's $1,285: a fact
  recorded correctly in one file and absent from the instrument built beside
  it. ⚠️ **When a brief's measured-facts table is assembled, grep the doc corpus
  for the claim before treating a finding as new.**
- ⚠️ **A dangling doc pointer the citation guard cannot see.**
  `TOKEN_EFFICIENCY.md` cited *"RUNBOOK quirk (i)"*; `RUNBOOK.md` has no quirk
  list and no (i). `check_doc_citations.py` only resolves `.md` **filenames**,
  so a pointer to a non-existent *section* passes green. Fixed here; the guard
  gap is unaddressed.
- ⚠️ **The brief's harness count pointed at the wrong coupling.** "8 of 65
  scripts name `index.html`, 7 as a URL" is true and irrelevant: **39 of 65
  reach page-scope globals inside `page.evaluate`** (`state.` in 36 files,
  `applyView` 11, `METRICS` 8, `buildLayers` 5, `SERVICES` 5, `CHROME_IDS` 4,
  `FULL_BUILD` 4, `noHover` 1 — 337 sites, no shared helper to patch once).
  Module scope hides all of them. Any `type="module"` step needs
  `window.__app = {…}` on the page side first. *Grep by symbol, not by
  filename, when the question is "what breaks if this scope changes".*
- **The script body parses unchanged as an ES module** — `node --check` on the
  extracted 6,748 lines as `.mjs` is clean; no top-level `await`/`this`, no
  inline `on*=` handlers, no `window.*` assignments. Parse ≠ run: strict-mode
  runtime violations are untested until the 65 scripts run against it.
- **The last banner always absorbs the boot.** At stage 1 (`a24aa91`) 1,555
  lines of "temporal lens" were really the tail; today 1,601 lines of "budget
  panel" are. `tools/codemap.py` indexes indent-4 declarations only, so an
  anonymous `map.on("load", async () => …)` has no row and its ~527 lines
  accrue to whatever symbol precedes it.
- **Codemap edges, classified** (script in the findings doc §4.2): same-section
  38%, chrome→kernel 24%, chrome→lens 8%, lens→kernel 6%, **lens→lens 3%**
  (22 of 28 inside the uncertainty-band trio). Ten lens-owned symbols are
  imported by peers (`exemptFrac` 5, `deviationStats` 4, …) — kernel candidates.
- **Source readers among the "11":** 7 (`build_site`, `check_cost_copy`,
  `check_doc_citations`, `codemap`, `test_build_site`, `test_codemap`,
  `test_window_labels`). `check_served_columns.py` and
  `build_reference_layers.py` only *mention* it; `refresh.yml` has no
  `index.html` trigger; `deploy.yml` triggers on `web/**`.
- **Only 9 top-level statements execute at load** in the whole script; the
  experimental full-only code is inert declarations in the public build.
- **Regression record:** 30 fix/revert commits of 165 on the file; 3 cross-lens
  leaks, all wrong conditions in shared dispatchers/gates — not file-shaped.
- Environment: the harness's `cd tools/profiling` **persists** across Bash
  calls — the batch after it failed on relative paths. Use absolute paths.
