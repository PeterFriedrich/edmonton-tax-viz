## 4. Technical Learnings

**The exempt premise was FALSE (central correction this session):**
- Long-assumed (in prior handoffs + `SPEC_revenue.md`): downtown gov / Legislature read
  low on revenue/acre because of **exempt** land. **Wrong.** `is_exempt` (proxy
  `Assessment Class 1 == 'NONRES MUNICIPAL/RES EDUCATION'`) flags only **3 parcels
  citywide**. Exempt institutional land is **absent from the taxable assessment roll
  entirely** — not flagged, not zeroed (only 46 zero-value rows dropped on load, all
  RES/COMM/FARMLAND). It contributes $0 to the numerator while its area sits in the
  boundary denominator, invisibly.
- The near-zero neighbourhoods (~57 with revenue/acre < $2,000) are **low taxable
  coverage** — few parcels over a big polygon. 20 are "RIVER VALLEY …", plus golf
  courses, "ANTHONY HENDAY …" ring-road margins, energy parks, undeveloped town centres.
  55/57 have <200 parcels.

**The distribution is a two-population mixture:**
- revenue_per_acre: min $2, median $17,592, p99 $60,967, max $249,973 — **5.2 orders
  of magnitude**. raw skew +5.83, log skew **−2.16** (log over-corrects → mixture sign).
- Trimming the near-zero tail moves log-skew toward 0: drop below $2,000 (57 neighbourhoods)
  → log-skew **−0.22** (≈ log-normal taxable core). **But $2,000 is a circular threshold —
  proves structure, NOT a production method.** The split must be by an independent
  category (land use), not by revenue.

**The fix — the Zoning Bylaw layer `fixa-tstc` (LOCKED design):**
- 11,510 zoning polygons citywide, codes + descriptions. Overlay on the 407 neighbourhood
  boundaries (EPSG:3400) → land-use **composition %** per neighbourhood.
- **Set aside = never + not-yet, threshold ≥ 0.90:**
  - **never** = River Valley (`A`, special-area `A1`–`A7`, `NSRVES`) / Natural (`NA`) /
    Parks (`PS`, `PSN`).
  - **not-yet** = Future Development (`FD`) + agricultural/rural (`AG`, `RR`) + industrial
    reserve (`EET*`).
  - Mixed (0.5–0.9) and all developed land **stay on the scale** (zoning = what's
    *allowed*, not *built*).
- **Why not-yet still scales:** set-aside keys off *zoning*, not revenue. The city rezones
  land as it develops → set_aside drops below 0.90 → it auto-rejoins the scale next refresh.
  Self-maintaining, **provided zoning is re-pulled each pipeline cycle.**
- **Validated in scratch:** tail (rev<$2k) median set-aside **0.99** vs developed **0.11**.
  At ≥0.90: **48 neighbourhoods set aside** (River Valley *, Anthony Henday *, ravines,
  golf courses, Mill Woods Park), **24 mixed kept on scale** (Cloverdale, Riverdale,
  Stillwater, etc.). **ZERO genuine underperformers in the tail** (`set_aside<0.3` was
  empty — the near-zero end is *entirely* non-developable land).

**Zoning categorization gotchas (DO NOT use keyword/prefix heuristics):**
- "Park" appears in industrial place-names: `EET*` = "Edmonton Energy & Technology
  **Park**" (industrial), `CP*` = "Century **Park**" (TOD redevelopment) — NOT green parks.
- The `A` prefix over-grabs: `AED` = "Arena & Entertainment District" (downtown!),
  `ALA` = "Ambleside Low Rise **Apartment**" (residential), `AUVC` = Ambleside commercial.
  The real river-valley `A*` codes (Muttart, Hawrelak, Fort Edmonton, Louise McKinney,
  Valley Zoo) ARE natural.
- **Build an explicit `code → category` dictionary** (~95 base codes; descriptions make
  each obvious). Parse the **first token** of `zoning` for the base code (suffixes like
  `RM h16` are height overlays).
- **Geometry must be cleaned before overlay:** raw polygons are invalid/mixed-dimension
  → geopandas `overlay` raises `GEOSException: Overlay input is mixed-dimension`. Fix:
  `buffer(0)`, drop empty + keep only Polygon/MultiPolygon.

**Visual decision:** set-aside neighbourhoods render **neutral grey** (not red/low) and
are **excluded from the colour-scale fit**. The full zoning-polygon overlay layer is a
**SEPARATE later product decision** (don't couple — it changes the viz from "revenue/acre"
to "revenue/acre + land-use overlay").

**Colour transform — still DEFERRED:** after the set-aside lands, re-run the skew test on
the set-aside-excluded set. If ≈ log-normal (likely), use **log** for colour; **sqrt** is
the fallback. **Height stays LINEAR** regardless (standing honesty choice).

**Urban3 framing (for the methodology doc):** Urban3's ~100× (Asheville Walmart $6,500/acre
vs downtown building $634,000/acre) is **parcel-level**, which self-categorizes land use.
We aggregate to neighbourhoods, which loses that — so the zoning layer is **methodological
compensation for our unit choice, not feature creep.** A narrower spread than Urban3's is
expected (aggregation), not a weakness.
