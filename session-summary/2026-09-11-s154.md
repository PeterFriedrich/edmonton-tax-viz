### 3c. ⚠️ `CLAUDE_CODE_CHILD_SESSION=1` — S153's correction was half right

- **Launch env of this session's `claude` (PID 628276): NO `CLAUDE*` vars.**
  `tmux show-environment -g`: none. So the tmux leak S153 found is gone.
- **Yet every Bash tool shell has** `CLAUDECODE`, `CLAUDE_CODE_CHILD_SESSION=1`,
  `CLAUDE_CODE_SESSION_ID`, `CLAUDE_CODE_BRIDGE_SESSION_ID`, `CLAUDE_EFFORT`,
  `CLAUDE_PID`, `CLAUDE_CODE_ENTRYPOINT`, `…EXECPATH`, `…MESSAGING_*`. **The
  harness injects them into tool shells.** The leak was real *in launch envs*;
  "not harness-set" was wrong for tool shells.
- **Rule:** `env` from a tool shell cannot detect a leak — read
  `/proc/<claude pid>/environ`. The SUBAGENT vars were absent in both, so
  `env | grep SUBAGENT` still reflects the launch line. Recorded in `TODO.md`
  (fable-session item, "REFINED 2026-09-11") and the `subagents-forced-to-haiku` memory.
- ⚠️ **S153 §5's parent-walk one-liner LOOPS FOREVER on this box** (it ran 120 s
  and was killed). `/proc/<tmux>/stat`'s comm is `(tmux: server)` — the space
  shifts `awk '{print $4}'` to the state field `S`. Use:
  ```bash
  p=$$; while [ "$p" -gt 1 ]; do echo "$p $(readlink -f /proc/$p/exe)"; p=$(ps -o ppid= -p $p | tr -d ' '); done
  ```
