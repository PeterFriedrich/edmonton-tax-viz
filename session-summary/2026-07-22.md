## 3. Technical Learnings
- **The three workstreams form a dependency chain, now sequenced:**
  1. **Organize the lenses** (CONTROLS_MATRIX §5 regroup) → produces BOTH the
     regrouped structure AND the `public|full` tags. One decision surface.
  2. **Build once** → regrouped controls + `BUILD` mode-gating + two-copy deploy.
  3. **Mobile CSS** reflows the FINAL grouping.
  Doing any downstream step before step 1 means redoing it.
- **Mobile separation seam:** render = shared (one deck.gl canvas); chrome =
  isolatable via `@media (max-width:…)` appended to `<style>`; touch interaction
  = a `matchMedia('(pointer: coarse)')` JS branch. All additive, desktop-safe.
- **The control grouping is tier-scrambled today:** on-screen top→bottom is
  `coloradj(T3) → toggle(T2) → palette(T3) → lens(T3) → views(T1) → layers(T2)`,
  so the most important control (the T1 view switcher) sits 5th, below three
  presentation modifiers, and Money's metric picker is special-cased out of
  `#layers` to the top while every other view's T2 lives inside it.
- **Deploy today:** single Pages site, `web/` uploaded whole by `refresh.yml`
  (`actions/deploy-pages`); URL `peterfriedrich.github.io/edmonton-tax-viz/`.
  GitHub Pages = ONE site per repo → "two links" = two PATHS, not two sites.
- **VERIFY-THE-PREMISE, again:** I claimed mobile tooltips were broken without
  testing; they work. Peter caught it (as with the #79 geocoding premise last
  session). Emulator ≠ real device for touch.
- **Key file locations this session:** `docs/MOBILE_USABILITY.md`,
  `docs/CONTROLS_MATRIX.md`, `docs/PLAN_public_release.md` §2a, `DECISIONS.md`
  (2026-07-22 line), `tools/profiling/shot-mobile.js`. Gating predicates in
