## 3. Technical Learnings

- ⚠️ **TWO RECORDED ASKS WERE WRONG, and both would have been checkably wrong to
  the recipient.**
  1. **`DATA_ISSUES.md` §6 said to ask Edmonton for "the numeric
     `neighbourhood_id` the City already publishes".** `24uj-dj8v` **already
     carries one** — `neighbourhood_numberr` — and it is **comma-joined on every
     one of the same 547 rows**. Asking a publisher to publish a field they
     already publish costs a report its credibility. Corrected in place.
  2. The same measurement made the report **better**, not just smaller: the id
     is **strictly more informative than the name**. Retired ids are absent from
     the boundary file `65fr-66s6`, so membership separates the three causes
     **mechanically** where names could only guess — **240 genuine straddles /
     238 renames / 69 duplications, 0 rows unclassified**. `1150` (OLIVER) and
     `2310` (GORMAN INDUSTRIAL WEST) are simply not in the 407-row file.
- ⚠️ **A "larger second defect" evaporated on checking, and checking is the only
  reason it did not get reported.** 5,252 non-comma permit rows carry a retired
  id (`CHAPPELLE AREA` 5,175 rows / 6,618 units — 12× the comma defect). It is
  **not a defect for us**: `src/load_assessment.py`'s `NAME_CORRECTIONS` already
  maps all three names. And those three are **exactly** the three non-comma
  names `DATA_ISSUES.md` §6 already recorded as missing the boundary file —
  found independently from the id direction, which is a confirmation, not a new
  finding. **Deliberately left out of the report**: bundling an unevidenced
  second complaint into a well-evidenced first one weakens both.
- ⚠️ **THREE DEFECTS IN THE STALENESS AUDIT'S OWN INSTRUMENT, each inflating
  apparent progress.** This is why pass 7 should fix the ledger before checking
  anything.
  1. **Annotating a checked item drops it out of its own cohort** — the 30–60d
     band is **8 today, not pass 5's 12**, because pass 5 annotated the 3 it
     checked with that day's date.
  2. **Pass 3's rule "accurate items were NOT annotated" makes an accurate item
     indistinguishable from an unchecked one, so later passes RE-CHECK it.**
     `THE RATIO AND USES PRISMS` and `A TRUE BIKEWAY LIFECYCLE` are both in
     today's 8 and were both verified in **pass 1**. A 25% re-check rate.

     `>60 d` is **1 item** by newest-date-in-item (last touched) and **18** by
     oldest-date (opened). The progress line's own *"remaining 24 items >60 d"*

  **65 top-level open boxes, 100 including nested**.
