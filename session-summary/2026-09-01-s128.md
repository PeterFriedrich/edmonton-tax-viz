## 3. Technical Learnings

### ⚠️ Confirm whether a sized capability REPLACES or JOINS what exists
"How heavy would a 50 m map be" was a question about **adding** a capability and
was read as a question about **changing** one. **Nothing in the measurements
distinguished the two readings**, so nothing caught it — four PR-review
checkpoints all verified the wrong deliverable correctly. Measuring a thing
carefully is not the same as having scoped it.

### A finer rendering audits the aggregate — second time now
Halving the cell exposed a defect the 100 m grid had **completely masked**:
three WESTMOUNT condo records (`4259396`/`4259412`/`4259420`, $859,500) whose
`lot_size` reads **0.505 / 0.218 / 0.277 — ownership shares summing to 1.000**,
not m². $859,500 on a nominal 1 m² lot = **$3.48B/lot-acre**. At 100 m that cell
merged with neighbours holding real lots and the needle vanished entirely.
The 100 m grid catching a month-old choropleth defect on its first render was
the same pattern. **Detail views are verification, not polish.**

### A red guard is a finding; re-pinning it is a separate decision
`check_value_anchors.py`'s `lot_needle_ratio` went **12 → 79**. The move was
**resolution, not data**. Re-pinned at **±50%, not the frozen group's ±25%**,
because **one degenerate record now sets it** and its stability across a
reassessment is unobserved. ⚠️ **A test enforced that split and failed**
(`test_tightened_anchors_are_actually_tighter_than_the_old_uniform_band`),
forcing the justification into the open — the guard working as designed. The
anchor now has its own test pinning the widening.

### The same pinned-constant defect will recur at every new constant
`"100 m"` was hardcoded at **11 user-facing sites**, so the first build rendered
93,201 fifty-metre cells under a legend reading *"Revenue per acre (100 m
cells)"* — **F4 exactly, at a different constant, four days later.** Fixed with
F4's own `{{token}}` machinery rather than a second mechanism.
⚠️ **The files DO carry `cell_m` and it is still not read for labels** — the
grids are lazy, so a data-derived label is empty on first paint. Unchanged from
F4's async lesson.

### A static test cannot check that a substitution FIRED
`data-tok` is a **valueless attribute**, so `el.dataset.tok === ""` — falsy —
and the truthiness test skipped every button. The buttons rendered
`{{cellGlass}} grid` **while every static check in `test_window_labels.py`
passed**. Caught only by looking at the DOM. → **`tools/profiling/verify-tokens.js`**,
falsified against that exact bug. Use `hasAttribute`, not `dataset.x`, for
valueless attributes.

### Documented measurements go stale silently
An HTML comment justifying the independent amenity bands cited
**1.6% / 21.8% / ~14×**. Its **own 100 m grid** then read **1.59% / 37.81% /
23.8×** — the school band moved when the schools CSVs refreshed 2026-08-23 and
nothing re-ran it. The argument got *stronger*; the numbers had been wrong for a
week. ⚠️ **These percentages are resolution-dependent** and move again if cell
size becomes selectable.

### `--skip-zoning` silently drops `exempt_frac` from the value grid
The first 50 m build was column-short (13 vs 14) because `exempt_levy` comes
from `load_zoning`. **Always compare `columns` between old and new grid files.**

### Environment quirks (this box) — all still true
- ⚠️ **`pkill` in a chain returns 144 and aborts it.** Use `kill <pid>`; get the
  pid from `ss -ltnp | grep ':<port>'`.
- ⚠️ **Playwright lives in `tools/profiling/node_modules`** — `/tmp` scripts
  cannot `require('playwright')`.
- ⚠️ **No GPU (SwiftShader).** Render/frame timings here are meaningless — the
  50 m GPU cost **has not been measured** and must be, on Peter's laptops.

- ⚠️ System `python` is 3.6.8 — use `.venv/bin/python`, `cd` first.
- Full pipeline run ≈ **112–123 s** with `--skip-png --skip-fire --skip-permits`.
